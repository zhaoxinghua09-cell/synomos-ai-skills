# todo-tracker（待办追踪）

**一句话定位**：把待办当作可追踪的数据对象来管理——增删改查、排优先级、设截止、管依赖、留审计，让 AI 替你回答「我有哪些待办」「这件事卡在哪」「先做哪个」。

**何时用**：用户要记任务、看清单、改状态/优先级/截止、理依赖、按优先级或截止挑下一个要做的事、要一份可审计的待办台账。
**何时不用**：需要团队协同看板/甘特图（本技能只管单人本地台账）；需要定时提醒推送（只记录不主动推送）；医疗/疗效/临床决策（明确不适用，见第一章边界）；需要网络同步或多端实时协作。

---

## 一、能力边界

**能做什么**
- 任务生命周期管理：创建 / 查看 / 更新 / 完成 / 删除 / 归档。
- 字段管理：标题、状态、优先级、截止日期、依赖、备注、标签。
- 查询与排序：按状态、优先级、截止、标签过滤；输出「下一步该做」建议。
- 依赖关系：标记「依赖某任务」，阻塞时提示不可启动。
- 审计留痕：关键变更写入 `audit` 日志（谁/何时/改了什么）。

**不能做什么（边界）**
- 非医疗器械 / 非医疗软件，无任何疗效或临床声明；不提供诊断、用药、治疗建议。
- 不做主动推送 / 闹钟；只记录，不主动打扰。
- 不联网同步；数据默认落在本地工作区文件，跨设备需自行拷贝或接后端（后端密钥见第八章）。
- 不替代项目管理平台；适合单人轻量台账，规模上限见下。
- 不解析自然语言模糊指令的「隐含依赖」——只认显式声明的依赖。

**可操作约束（评测补齐）**
- 存储位置：默认 `<工作区>/todos/todos.json`；可用 `store:` 参数指定绝对路径。
- 并发：单文件写入为串行追加/覆盖，避免同一文件多进程并发写；若检测到文件锁占用，报错而非静默覆盖。
- 数据量上限：单文件建议 ≤ 5000 条任务；超出建议按项目拆文件。
- 字段长度：标题 ≤ 200 字；备注 ≤ 2000 字；超出截断并提示。
- 时间格式：截止统一 `YYYY-MM-DD` 或 `YYYY-MM-DDTHH:MM`（本地时区），非法格式报错。

## 二、输入约束与输出承诺

**输入（用户/上游一句话或结构化参数）**
- 自然语言：如「加个任务：写完周报，周五前，优先级高，依赖『收集数据』」。
- 结构化字段（可选）：`title`(必填)、`priority`(P0–P3)、`due`(日期)、`deps`(任务ID/标题列表)、`tags`(列表)、`note`。
- 指令动词：`add` / `list` / `show` / `update` / `done` / `remove` / `next` / `blocked`。

**输出承诺**
- 每次成功变更后回显：任务 `id`、标题、状态、优先级、截止、依赖摘要。
- `list` 默认按「未完成 → 优先级 → 截止」排序，并标注阻塞项。
- `next` 返回「当前最该做的 1–3 条」（未被依赖阻塞、优先级最高、截止最近）。
- 所有输出为中文；任务原文保留用户措辞，不擅自改写语义。
- 失败必带错误码（见第十章）与可操作修复建议，不静默失败。

**意图表**

| 意图 | 触发词（中/英） | 映射到动作 | 示例说法 |
|---|---|---|---|
| 创建任务 | 添加/创建/记一下任务；add/todo/new task | `add` | 「帮我记个任务：交月报，下周一前」 |

| 改任务 | 改/更新任务；update/edit | `update` | 「把『交月报』优先级调到最高」 |
| 完成 | 完成/搞定/勾掉；done/complete | `done` | 「『收集数据』做完了」 |
| 删除 | 删掉/移除任务；remove/delete | `remove` | 「把过期的『订会议室』删了」 |
| 下一个 | 先做哪个/接下来做啥；next/what next | `next` | 「我现在该做哪个？」 |
| 阻塞项 | 卡在哪/被什么挡住；blocked | `blocked` | 「有哪些任务被卡住了？」 |

**示例对话**
- 用户：「加任务：写完 Q3 总结，10 月 1 日前，高优先级，依赖『汇总数据』。」
- AI：`add` → 建 id `t-007`，状态 `todo`，优先级 `P0`，due `2026-10-01`，deps `[汇总数据]`；回显确认。
- 用户：「先做哪个？」
- AI：`next` → 返回未被阻塞的最高优先级项；若 `t-007` 因依赖未完成则提示「先完成『汇总数据』」。

## 四、常见错误与反模式

**结构化 FAQ（反模式 → 正确做法）**

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 把截止写成「尽快」「这周」等模糊词 | 无法排序、无法判阻塞 | 用明确日期 `YYYY-MM-DD` |
| 用同一个标题建多个任务 | `id` 冲突、更新歧义 | 标题唯一；重复时先 `list` 查重 |
| 隐式依赖不声明 | 阻塞检测失效 | 显式 `deps:[...]` |
| 把医疗/治疗当待办 | 越界、违规 | 拒绝并提示不适用（第一章） |
| 删除代替完成 | 丢审计、台账失真 | 用 `done` 留痕 |
| 一次塞 5000+ 条不拆文件 | 超量、读写慢 | 按项目拆 `todos.json` |
| 把密钥/口令写进任务备注 | 泄露风险 | 见第八章，凭据不进对话不进任务 |

**高频 Q&A**
- Q：任务丢了？A：先 `list` + 检查 `store:` 路径是否指错文件；审计日志在 `todos/audit.json`。
- Q：依赖循环？A：建依赖时检测环，报错 `E-CYCLE` 并列出环路，不写入。
- Q：改了标题找不回？A：`update` 改标题会保留 `id`，用 `id` 检索而非旧标题。
- Q：过期任务一堆？A：`list due:<今天` 查看；建议 `done` 或 `remove`，勿批量静默删。

| 步骤 | 动作 | 关键规则 |
|---|---|---|
| 1 | 解析意图与字段 | 抽取动词→动作；缺 `title` 则反问，不臆造 |
| 2 | 定位存储 | 用默认或 `store:`；文件不存在则初始化空台账 |
| 3 | 校验 | 日期格式、依赖存在性、环检测、字段长度 |
| 4 | 执行 | add/update/done/remove；写 `updatedAt` |
| 5 | 留痕 | 变更写入 `audit.json`（action, id, before, after, ts） |
| 6 | 回显 | 按第二章格式输出结果与下一步建议 |
| 7 | 失败兜底 | 命中错误码→第十章处理，绝不静默 |

## 六、关键事实速查

- 状态机：`todo → doing → done`；可 `remove`（删）或归档。
- 优先级：`P0`(最高) > `P1` > `P2` > `P3`；缺省 `P2`。
- 排序默认：`未完成 → 优先级升序 → 截止升序`。
- 阻塞：`deps` 中任一未完成 → 该任务不可 `doing`，`next` 跳过。
- 存储：`<工作区>/todos/todos.json` + `todos/audit.json`。
- 时间：本地时区；`due` 仅日期则按当天 23:59 计。
- `id` 规则：`t-` + 自增序号（如 `t-007`），全局唯一。
- 审计：每次写操作一条记录，不可追加式修改历史。

## 七、铁律（PROHIBITED）

- 禁止把待办用于医疗诊断、治疗、用药、临床决策等越界用途。
- 禁止静默失败：任何异常必须返回错误码与修复建议。
- 禁止臆造任务标题/截止/依赖；缺字段须反问。
- 禁止在未声明依赖时谎称「无阻塞」。
- 禁止用 `remove` 冒充 `done` 来「清账」。
- 禁止把密钥、口令、令牌写入任务或备注（见第八章）。
- 禁止覆盖正在被锁定的文件；检测到锁须报错 `E-LOCK`。
- 禁止改写用户任务原文的语义；只可规整格式。

## 十、错误处理

| 错误码 | 触发 | 处理 |
|---|---|---|
| E-BADTIME | 截止格式非法 | 提示正确格式 `YYYY-MM-DD`，要求重输，不写 |
| E-NOTFOUND | 操作 id/标题不存在 | 列出相似任务，建议 `list` 或 `add` |
| E-CYCLE | 依赖成环 | 列出环路，拒绝写入，建议拆依赖 |
| E-LOCK | 文件被占用 | 报错，等待重试或换 `store:`，禁止覆盖 |
| E-NOPERM | 无写权限 | 降级内存模式，提示导出路径 |
| E-DUP | 同标题已存在 | 提示复用或改名，不静默建重 |
| E-OVERSIZE | 单条超长 | 截断并提示上限 |
| E-OOR | 越界用途（医疗等） | 拒绝，说明边界（第一章） |

**通用兜底**：捕获任何未预期异常 → 返回 `E-UNKNOWN` + 上下文摘要 + 「数据未变更」，绝不静默成功。
