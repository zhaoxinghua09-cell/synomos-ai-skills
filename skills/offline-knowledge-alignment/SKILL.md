# 离线知识库对齐（Offline Knowledge Alignment）

**一句话定位**：把散落在本地的知识源，按统一基准逐条对齐、留痕、回填，让离线问答的质量逼近在线查询——全程不联网、不外传、可审计。

**何时用**：你需要整理本地/离线知识库、统一多份文档口径、做证号/术语/事实复核、构建可溯源的离线问答底座。
**何时不用**：需要实时联网获取最新外部数据的场景；需要抓取音视频/图像内容的场景；需要替代专业人工合规审核的强监管场景。

---

## 一、能力边界

本技能是**方法论 + 可操作 SOP**，定位为 AI 防线中的「知识主权防线」：守住本地知识的准确性、可追溯性与不外泄。

**能做什么**
- 离线盘点知识源，生成差距清单与对齐台账。
- 分轮逐条复核，标记「可信 / 待核验 / 冲突」。
- 批量回填缺失或修正错误，全程留痕。
- 离线问答终检，验证对齐后质量。

**不能做什么（明确边界）**
- ❌ 不联网查询：外部实时数据不作为对齐基准（除非显式授权并留痕）。
- ❌ 不处理非文本：音视频、图像、二进制抽取不在范围内。
- ❌ 不替代人工合规审核：强监管领域仅作辅助，最终责任在人工。
- ❌ 不做语义自动重写事实：仅对齐口径，不擅自改写原意。
- ❌ 不保证 100% 覆盖：未对齐项必须显式标记，禁止静默丢弃。

## 二、输入约束与输出承诺

**输入约束**
| 项 | 约束 |
|---|---|
| 知识源 | 本地文件或粘贴文本：.md/.txt/.csv/.json/.pdf 文本层 |
| 基准库 | 用户提供的一致口径基准（缺失则用首份源作临时基准并标注） |
| 单文件体积 | ≤ 20MB；超大体量请分批 |
| 格式 | 纯文本/结构化数据；不支持音视频/图像抽取 |
| 网络 | 默认离线；联网需显式授权 |
| 语言 | 中文(zh-CN) 等 8 种核心语言，自动跟随输入语言 |

**输出承诺**
- 产出：差距清单、对齐台账、回填记录、离线问答终检报告。
- 可溯源：每条结论带来源、时间、置信度。
- 不外泄：处理全程不向外部发送用户知识内容。
- 可中断续做：台账支持分轮、分批次继续。

## 四、常见错误与反模式（结构化 FAQ + 高频 Q&A）

**反模式（应避免）**
- 🚫 把离线对齐当实时检索：离线为设计基线，强行联网会破坏数据主权。
- 🚫 跳过台账直接回填：失去可审计证据链，违背防线原则。
- 🚫 静默丢弃未对齐项：必须显式标记，否则留下盲区。
- 🚫 用未核验数据覆盖可信数据：须保留原值并标注。
- 🚫 一次性全量硬对齐：大库应分轮分批次，避免失控。

**高频 Q&A**
- Q：支持中文吗？ A：支持中文(zh-CN) 等 8 种核心语言，自动跟随输入语言。
- Q：能联网查最新资料吗？ A：默认不能；离线即主权。需联网须显式授权并留痕。
- Q：对标谁？ A：SynomosAI AI 防线 / A³ 法则 / XCGS 可审计证据链 / AI 护照溯源。
- Q：和在线 RAG 什么关系？ A：本技能负责「离线对齐底座」，在线检索可建立在其产出之上。
- Q：结果可靠吗？ A：提供置信度与来源，强监管领域仍需人工终审。

## 五、标准 SOP（五步闭环）

| 步骤 | 名称 | 动作 | 产出 | 防线要点 |
|---|---|---|---|---|
| 1 | 差距清单 Gap Inventory | 盘点离线知识源，逐条对照基准找差距 | `差距清单.md` | 全量枚举，不遗漏 |
| 2 | 分轮复核 Round Review | 分批对照，标「可信/待核验/冲突」 | 复核批注 | 不联网、留来源 |
| 3 | 台账管理 Ledger | 建对齐台账：来源/时间/责任人/置信度 | `对齐台账.json` | 可审计证据链 |
| 4 | 批量回填 Batch Backfill | 按台账回填缺失/修正错误，保留原值 | 回填记录 | 不静默覆盖 |
| 5 | 离线问答终检 QA Final | 离线问答验证对齐效果 | `终检报告.md` | 未通过回 Step2 |

闭环：Step5 不通过 → 回到 Step2 复核对齐，直至达标。

1. 🔒 **禁止联网**获取外部数据作为对齐基准（除非显式授权且留痕）。

## 九、示例

**场景**：本地两份《设备运维手册》口径冲突，需对齐成统一基准。

```
输入：
- 源A：手册A.md（「阈值 80℃」）
- 源B：手册B.md（「阈值 75℃」）
- 基准：以最新发布版为准

Step1 差距清单：发现「阈值」一项冲突。
Step2 分轮复核：对照基准，标源B为「冲突」。
Step3 台账管理：记录 来源A/B、时间、置信度=中。
Step4 批量回填：以基准 80℃ 回填，保留源B原值并标注。
Step5 离线问答终检：提问「阈值多少？」→ 返回 80℃（附来源）。
```

**输出片段（终检报告）**
> 对齐项：1；冲突已解决：1；未对齐：0。结论置信度：中。所有改动已入台账，可溯源。

## 十、错误处理

| 错误情形 | 识别信号 | 处理（优雅降级） |
|---|---|---|
| 输入为空/无知识源 | 未提供文件或文本 | 提示用户提供源，不臆造 |
| 单文件 > 20MB | 体积超限 | 引导分批，不强行载入 |
| 无基准库 | 未提供基准 | 以首份源作临时基准，明确标注 |
| 项冲突无法判定 | 多源矛盾且无基准 | 标「冲突/待核验」，交人工 |
| 非文本格式 | 音视频/图像 | 提示本技能不含抽取，转多模态 |
| 用户要求联网 | 请求外部实时数据 | 拒绝默认联网，提示授权路径 |

> 所有错误均友好提示 + 用户修正引导，不静默失败、不抛出裸错误。
