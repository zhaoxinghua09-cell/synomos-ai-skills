# research-methodology · 调研方法论

> 发声大使：诺源(Arche)（源/根方法论）· 品牌归属 SynomosAI · 版权 SynomosAI · 许可 MIT
> 治理底座：SynomosAI XCGS / A³ Laws / AI Passport Regime / AI-world coinhabitation

## 定位与「何时用 / 何时不用」

**它是什么**：一套把「模糊的调研需求」转成「可溯源、可证伪、可交付」结果的执行方法论。核心是 PDCA（Plan→Do→Check→Act）在调研场景的落地，配四档分级与质量门禁。

**何时用**
- 用户要查一个课题、做竞品/市场/技术/文献情报、需要多源验证或查证事实。
- 用户要产出报告、方案、决策简报，且结论必须有来源支撑。
- 来源冲突、信源质量参差、需要判断「信谁」。

**何时不用**
- 纯闲聊、常识问答、无需证据链的轻量提问（走快档也嫌重时直接普通回答）。
- 实时行情/股价/秒级数据——本技能不持数据源，仅给方法与门禁。
- 医疗/法律/财务的合规结论——只给方法论与去处，不下专业判定（见铁律）。

## 一、能力边界

| 维度 | 本技能能做的 | 本技能不能做的 |
|---|---|---|
| 深度 | 快/标/深/重四档，档随问题升 | 替你拍板商业/临床/法律最终决策 |
| 来源 | 设计检索、交叉验证、证据分级 | 保证 100% 引用可解析（目标非保证） |
| 范围 | 给定边界内做满，范围外明说未做 | 自动扩到未授权的话题域 |
| 交付 | 五段式简报 + 溯源包 + AAR 复盘 | 替代领域专家的专业背书 |

**四档服务（边界即契约）**
- **快档**：单源快速答，适合日常问答。
- **标档**：≥2 源交叉，适合一般查询。
- **深档**：全流程 PDCA，适合方案/报告/交付。
- **重档**：全流程 + 多角度 + 第一性原理，适合理论/进化/规划。

> 切换条件：出现「决策依赖」「来源可能冲突」「需对外交付」任一信号，即升档。

## 二、输入约束与输出承诺

**输入约束（缺则退回补 Brief，见第十章）**
1. 必须给出「调研目标」与「用途」（决定档位）。
2. 必须给出「范围/边界」（时间、地域、语言、主题）。
3. 必须给出「交付格式」与「验收标准」（否则按五段式默认）。
4. 敏感/受限数据不进对话，凭据从保险库读（见第八章）。

**输出承诺**
- 每条结论附溯源包 `{url, source_type, snippet, 抓取日期, doi}`。
- 明确标注证据等级（GRADE）与概率词（ICD 203 统一）。
- 查不到 → 明说「未查到」，不编造。
- 范围外 → 明说「未做」，不计缺陷。
- 引用可解析率 100% 是目标；FACTS 顶级模型引用可解析率 <70% 时亮牌提示风险。

## 四、常见错误与反模式（FAQ + 高频 Q&A）

**反模式（禁止模仿）**
- ❌ 单源即下结论 → 标档起必须 ≥2 源交叉。
- ❌ 快档流程套深档问题 → 决策依赖必须升档。
- ❌ 溯源包漏填 `doi`/`抓取日期` → 必填字段缺一不可。
- ❌ 来源冲突时「和稀泥平均」→ 必须标注分歧与各自证据等级。
- ❌ 把方法论当专业结论 → 医疗/法律/财务只给框架与去处。

**高频 Q&A**
- Q：查不到就是没有吗？A：不是。只说明「本次未查到」，并说明检索范围与盲区。
- Q：引用打不开怎么办？A：标注「待核验/不可解析」，不计入可解析率，亮牌提示。
- Q：快档和深档差在哪？A：快档单源快速答；深档走完整 PDCA + 质量门禁 + 复盘。
- Q：来源互相矛盾？A：三角验证，分别给证据等级，标注分歧，不替你拍板。
- Q：能直接给投资建议吗？A：不能。只给调研方法与信源，决策由你做。

## 五、标准 SOP（五步 + 四档）

| 步骤 | 阶段 | 动作 | 产出 |
|---|---|---|---|
| 1 | Plan | 写 Research Brief（七要素）并呈批 | 已批 Brief |
| 2 | Do | Query 改写 + ≥3 路并行检索 + PRISMA 去重 | 原始证据集 |
| 3 | Check | 三角验证 + GRADE 分级 + ICD 203 概率词统一 | 分级结论 |
| 4 | Gate | 调用 research-quality-gate v1.7 过门禁 | 通过/退回 |
| 5 | Act | 五段式简报 + 溯源包 + AAR 复盘固化 | 交付物 |

**七要素 Research Brief**：目标 / 范围 / 核心问题 / 方法 / 来源计划 / 交付格式 / 验收标准。
**铁律前置**：未呈批不检索。

## 六、关键事实速查

- **PRISMA**：系统检索去重与筛选报告规范（用其流程做去重）。
- **GRADE**：证据分级（高/中/低/极低），标注每条结论等级。
- **ICD 203**：概率词统一表（如「可能/很可能」对应区间），避免模糊。
- **FACTS**：引用可解析率指标，<70% 亮牌。
- **research-quality-gate v1.7**：质量门禁，SOP 第 4 步强制调用。
- **溯源包字段**：`{url, source_type, snippet, 抓取日期, doi}`。
- **AAR**：After-Action Review 复盘，把流程固化回技能/记忆。

---

## 七、铁律（PROHIBITED）

1. **未呈批不检索**——无 Brief 不动手。
2. **查不到明说没查到**——绝不编造或脑补来源。
3. **范围外未做不计缺陷**——不偷偷扩域。
4. **先查国际标准/官方原文再输出**——不二手转述下结论。
5. **引用可解析率 100% 是目标非保证**——FACTS<70% 必须亮牌。
6. **跨域必过门禁**——深/重档强制 research-quality-gate。
7. **不下专业终裁**——医疗/法律/财务只给方法与去处。
8. **凭据不进对话**——敏感数据从保险库读，不落明文（见第八章）。

---

## 八、输入输出依赖（凭据从保险库读，不进对话）

- **输入**：用户提供的 Brief、范围、交付要求；如需受限数据源，凭据经 `unified-credential-vault` / `dpapi-local-vault` 读取，**绝不打印、不进对话、不写日志**。
- **输出**：五段式简报、溯源包、AAR 记录；可落 `DECISIONS.md`（决策）与记忆（流程）。
- **跨技能依赖**：`research-quality-gate`（门禁）、`ai-governance-audit-chain`（审计链）。该依赖失败时降级为「人工标注 + 明说未过门禁」，不静默跳过。
- **无外部 API 硬依赖**：本技能为方法论文档，国内网络可用，不发起自身网络请求。

## 九、示例（端到端演示）

**场景**：用户「调研『AI agent 身份码』2026 年主流标准，给我一页简报。」

**① Research Brief（七要素）**
- 目标：厘清 2026 agent 身份码主流标准与收敛态势
- 范围：2026 年内、中/英/国际标准、公开材料
- 问题：哪些框架成主流？是否收敛到「一 agent 一 ID」？
- 方法：≥3 路并行（标准正文 / 行业报告 / 厂商公告）
- 来源计划：W3C AIP、ISO/IEC 42001、Okta for AI Agents、IMDA
- 交付：五段式一页简报
- 验收：每条结论带溯源包 + GRADE

**② 检索与验证**：三路并行 → PRISMA 去重 → 三角验证 → GRADE 标「高」。

**③ 五段式简报（节选）**
- 结论：行业收敛于「每 agent 唯一可溯源 ID」。
- 证据：W3C AIP 进 IETF 草案(06)、Okta for AI Agents GA(04-30)、IMDA 首发国家框架(01)。
- 分歧：强制时点各国不同，标注「待官方公报」。
- 溯源：每条附 `{url, source_type, snippet, 抓取日期, doi}`。
- 行动：建议采纳身份码 + 审计链回治理缺口。

**④ AAR**：流程固化——「收敛态势」写入记忆，本 Brief 模板沉淀为可复用样例。

## 十、错误处理

| 错误码 | 触发 | 处理动作 |
|---|---|---|
| E1 输入不全 | 缺目标/范围/交付 | 退回补 Research Brief，列出缺失要素，不臆测 |
| E2 来源冲突 | 多源结论矛盾 | 三角验证，分别标 GRADE，标注分歧，不替用户拍板 |
| E3 检索失败/无果 | 查不到 | 明说「本次未查到」+ 说明检索范围与盲区，可降级档位 |
| E4 引用不可解析 | 链接失效/无 doi | 标「待核验/不可解析」，不计可解析率，FACTS<70% 亮牌 |
| E5 门禁失败 | quality-gate 未过 | 降级为人工标注 + 明说「未过门禁」，不静默放行 |
| E6 超范围请求 | 触及未授权域 | 明说「范围外未做」，不扩域 |
| E7 专业终裁请求 | 医疗/法律/财务判定 | 拒下终裁，给方法论与去处 |

**通用原则**：任何异常都「明说状态 + 给替代路径」，不让用户误以为已完成。纯文档型技能无运行时崩溃风险，错误以「可读提示」形式返回，不抛栈、不静默。
