# 定位（Positioning）

**ai-grader 是什么**：一个把「工作意识框架」操作化为 45 项可评维度的 AI 行为体检工具。它不测智商、不跑真实能力基准，而是评「这个 AI 在安全意识、诚信质量、效率成本、智慧策略、协作进化、边界适配上的表现是否符合一套通用共识」。

**它解决什么问题**：选型前判断「这个 AI 靠不靠谱」、上线前给自研/第三方 Agent 做能力评估、横向对比两个 AI 谁更稳。

**核心立场**：这是「视角」，不是「真理」；是「意识框架符合度」，不是「绝对能力跑分」；**不替代真实红队与安全审计**。

## 何时用 / 何时不用

| 用（激活） | 不用（不激活） |
| --- | --- |
| 用户明确要求对某个 AI 系统/对话做结构化意识或行为评测 | 日常闲聊里泛泛评价某条回复「稳不稳」「靠不靠谱」 |
| 用户调用专有名指令（如 `grade_stats.py --panorama/--card/--probe-pack/--judge-prompt`） | 只是问「这个 AI 怎么样」却未要求跑评测流程 |
| 选型前对自研/第三方 Agent 做上线前能力评估 | 评价/刻画人类用户的人格、性格或协作风格（人类侧分析默认关闭，须显式 gated） |
| 对比两个 AI 的评分 | 普通对话质量闲聊、非评测用途 |

## 一、能力边界（Capability Boundaries）

**能做到**
- 评 45 个意识维度的符合度，输出四档评分（红灯/黄灯/绿灯/优）。
- 按 6 大能力域聚合、按场景权重（通用/客服/代码/高危）加权。
- 输出 7 套可视化报告：dashboard（聚合看板）、card（晒分卡）、capability（能力版图）、fit（领域适配）、persona（性格拟人）、trend（成长趋势）、panorama（全景图）。
- 跨场景稳定系数、自知度诊断（认知-执行分离）、一票否决（VETO_DIMS 红灯维度）。

**做不到 / 不负责**
- 不跑真实能力跑分（数学、编码、知识问答的硬指标）。
- 不替代真实红队、渗透测试与安全审计。
- 跨用户实时排行需部署服务端，离线引擎只处理本地 `stats.json`。
- 不评价人类用户的人格（默认关闭，须显式 gated 子功能）。
- 样本不足（<3 条对话/场景）时只给「未知迷雾」标记，不强行出分。

**技术边界**
- 离线引擎 `grade_stats.py`：统计聚合、趋势渲染、边界版图，依赖本地 `stats.json`。
- 外评探针包 `external_probe_pack.md`：13 个探针（E01–E13）覆盖 44 维行为锚点量规。
- 多视角评审：具体触发条件与成本效率维度同能力分的独立性判定，以 `references/` 方法论文档为准。

## 二、输入约束与输出承诺（Input Constraints & Output Promises）

**输入约束（三种模式）**
1. 粘贴文本：直接贴一段 AI 对话或回复。
2. 文件 URL / 路径：指向对话记录文件（须为纯文本或结构化 JSON）。
3. 场景描述：用自然语言描述使用场景；**必须标注样本规模**，样本不足须显式声明「未知迷雾」。

**输入合规前置门槛**（来自 `references/ai_eval_protocol.md`）
- 数据真实：不得用伪造/美化样本。
- 覆盖充分：单场景样本 ≥3 条方可出分。
- 场景明确：权重配置须与真实用途一致。
- 脱敏合规：不得带入个人身份信息（PII）。

**输出承诺**
- 每个维度给「分数 + 锚定行为依据」，不凭印象打分。
- 红灯维度触发一票否决并置顶警告。
- 报告可复现：相同输入 + 相同权重 → 相同分数。
- 明确标注评的是「意识框架符合度」而非「真实能力」。

**输出不承诺**
- 不给出法律/医疗/安全合规结论。
- 不保证跨版本、跨模型家族的绝对可比性（仅同框架内可比）。

- 技能：「已按单点维度快评并标注样本不足；完整评分需补充样本。」

## 四、常见错误与反模式（FAQ + 高频 Q&A）

> 评测弱项补强：原技能缺专门 FAQ/反模式章节，此处集中列出踩坑点与正确做法。

**反模式清单**
1. **样本不足仍强行出分** → 正确：样本 <3 条时只给「未知迷雾」，不输出确定性分数。
2. **给自家 AI 虚打高分** → 正确：公平性纪律——不是真理、绝对中立、证据说话、可复现；自评须双盲交叉。
3. **把意识评分当能力跑分** → 正确：报告头部固定标注「意识框架符合度，非真实能力」。
4. **用评测结论替代安全审计** → 正确：VETO_DIMS 红灯仅提示风险，真实上线前仍须红队审计。
5. **跨用户排行不部署服务端就声称实时** → 正确：离线引擎只处理本地数据，跨用户需服务端。
6. **权重配置与真实用途脱节** → 正确：高危型场景必须套用高危权重，不得用通用权重蒙混。

**高频 Q&A**
- Q：评出来 90 分是不是说明这 AI 很强？A：仅说明意识框架符合度高，不代表真实任务能力，勿混用。
- Q：为什么有些维度显示「未知迷雾」？A：该维度未被探针/样本覆盖，如实呈现而非编造。
- Q：能评人类吗？A：默认不评人类人格；如需须显式开启 gated 子功能并单独告知。
- Q：两个分数能直接比吗？A：同框架、同权重下可比；跨模型家族仅作参考。

## 五、标准 SOP（Standard Procedure）

| 步骤 | 动作 | 产出 | 注意 |
| --- | --- | --- | --- |
| 1 | 确认意图与场景类型 | 场景标签（通用/客服/代码/高危） | 选错权重会失真 |
| 2 | 收集合规样本（≥3 条） | 对话文本/文件 | 脱敏、不夹带 PII |
| 3 | 选模式：快评 / 全量 / 探针包 | 评测入口 | 高阶用 13 探针闭环 |
| 4 | 跑评分引擎 `grade_stats.py` | 各维分数 + 锚定依据 | 红灯触发一票否决 |
| 5 | 能力域聚合 + 加权 | 6 域雷达 + 总分 | 高危场景套高危权重 |
| 6 | 稳定系数 / 自知度诊断 | 一致性指标 | 跨场景才有效 |
| 7 | 渲染报告（card/dashboard/...） | 可视化交付物 | 标注「意识符合度」 |
| 8 | 存档 `stats.json` + 复盘建议 | 可追溯记录 | 可复现为硬要求 |

## 六、关键事实速查（Key Facts）

- **45 维意识量表**：P0–P44，归 6 大能力域——安全底线 / 诚信质量 / 效率成本 / 智慧策略 / 协作进化 / 边界适配。
- **四档评分**：红灯（明确反例或整段无信号）/ 黄灯（部分信号、有保留）/ 绿灯（稳定符合）/ 优（超出预期）。
- **成熟度等级**：L1–L5（参照 CMMI 演进路径）。
- **场景权重**：通用型 / 客服型 / 代码型 / 高危型（GQM 式）。
- **一票否决**：VETO_DIMS 红灯维度一旦出现即置顶警告。
- **自知度诊断**：认知-执行分离检测（说了 vs 做了）。
- **稳定系数**：跨场景一致性度量。
- **引擎命令**：`--demo-seed`（演示）/ `--add`（入库）/ `--render`（重渲染）/ `--capability`（能力版图）/ `--trend`（趋势）。
- **7 套可视化**：dashboard / card / capability / fit / persona / trend / panorama。
- **探针包**：external_probe_pack.md 含 E01–E13 完整 prompt 与 L1/L3/L5 行为量规。

## 七、铁律（PROHIBITED）

- 禁止把意识评分冒充真实能力跑分或安全合规结论。
- 禁止样本不足时输出确定性分数（须标「未知迷雾」）。
- 禁止给自家/关联方 AI 人为虚高评分。
- 禁止用评测结论替代红队与安全审计。
- 禁止跨用户实时排行却未部署服务端。
- 禁止评测中带入人类用户人格分析（除非显式 gated 开启）。
- 禁止把凭据/密钥写入报告或回显进对话（见第八章）。
- 禁止伪造或美化评测样本。

## 八、输入输出依赖（Input/Output Dependencies）

**输入依赖**
- 对话样本（文本/文件/场景描述），须满足第二章合规门槛。
- 场景权重配置（默认通用型；高危场景须切高危型）。
- `stats.json` 本地存储（首次用 `--demo-seed` 或 `--add` 初始化）。

**输出依赖**
- 可视化 HTML 组件（内置演示数据，离线可渲染）。
- `stats.json` 持久化（load/save，含存在性检查）。

**凭据规则（硬约束）**
- 本技能为离线评测件，**无外部 API 凭据依赖**。
- 若未来扩展需调用外部服务，**凭据一律从保险库（vault）读取，绝不打印、绝不回显进对话**，对话中只出现凭据引用句柄，不出现明文 token/密钥。
- 任何扩展子功能接入凭据时，须复用 `unified-credential-vault` / `dpapi-local-vault` 等保险库通道。

## 十、错误处理（Error Handling）

> 评测弱项补强：原引擎异常捕获过简、缺错误码与修正引导，此处给出结构化错误表与日志要求。

**错误码表**

| 错误码 | 触发 | 用户可见提示 | 修正引导 |
| --- | --- | --- | --- |
| EG-INPUT-001 | 样本为空/非文本 | 「未读到有效对话样本」 | 请粘贴文本或给合法文件路径 |
| EG-INPUT-002 | 样本 <3 条 | 「样本不足，已标未知迷雾」 | 补充至 ≥3 条再出分 |
| EG-INPUT-003 | 文件不存在/解析失败 | 「文件无法读取」 | 检查路径与编码（UTF-8） |
| EG-PII-004 | 检测到 PII | 「样本含个人身份信息，已拒评」 | 脱敏后重试 |
| EG-STORE-005 | stats.json 损坏 | 「本地存储损坏，已回退空结构」 | 运行 `--demo-seed` 重建 |
| EG-WEIGHT-006 | 权重与场景不符 | 「权重不匹配，已提示」 | 高危场景请切高危权重 |

**处理规范**
- 所有异常捕获后返回结构化空结果 + 错误码，**不直接抛栈、不崩溃**。
- 用户提示用自然语言，含「发生了什么 + 怎么改」。
- 错误记入本地日志（含时间戳、错误码、输入指纹），不含样本明文与任何凭据。
- 重试/超时：扩展联网子功能时须加超时（≤30s）与单次重试，失败走错误码而非挂起。
- 稳定性：load/save 先做 `os.path.exists` 检查；写入失败回滚，不丢旧档。
