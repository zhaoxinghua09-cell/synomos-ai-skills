# 可追溯性审计团（标准情报·白皮书·追溯审计）

面向医疗器械质量体系，提供"标准情报 → 报告成稿 → 审计统筹"三线协作的端到端追溯审计能力。把监管标准依据、白皮书级报告撰写，与覆盖 UDI / 批次 / 供应链的证据链追溯核验，整合为可对外主张的审计 SOP（对标会计师事务所审计组：标准依据 → 证据链审计 → 报告成稿）。本 Skill 自包含，不依赖外部 Agent 文件，可独立运行。

三线分工：**线一·标准情报**（标准雷达）提供适用条款与动态；**线二·白皮书/报告成稿**（成稿线）把结论结构化；**线三·审计统筹（溯源官）**编排全流程并亲自执行核心证据链审计。专业产出由对应线独立完成，统筹线只做编排与汇编，不代写。

## 定位

**何时用**
- 医疗器械追溯体系 audit：UDI 赋码与上报、批次管理、供应链上下游追溯链路核验。
- 质量体系审核：ISO 13485 / 医疗器械 GMP / MDSAP 下的可追溯性条款核查。
- 标准情报对标：EU MDR 2017/745、FDA QSR 与 UDI、ISO 15223-1、IEC 62366、GS1、MDSAP 等适用条款与动态。
- 理论白皮书/技术报告撰写；法规符合性核查（注册、飞检、召回、投诉联动）。
- 需要"通过 / 有条件通过 / 不通过"分级及整改建议的审计结论。

**何时不用**
- 非医疗器械、非可追溯性议题 —— 不在范围内。
- 要求代为监管申报、代替监管认证 —— 本团不做合规承诺或保证（见第七章铁律）。
- 需要医学临床判定或产品注册路径裁定 —— 转 MedXpert 专业角色。

## 一、能力边界（In/Out scope）

**本技能做（In）**
- 适用条款清单 + 对标简报 + 差距分析 + 法规预警（线一）。
- 结构化追溯审计报告 / 白皮书章节 / 技术报告（线二）。
- 三锚证据链审计（身份锚 / 来源锚 / 行为锚）与结论分级（线三）。
- 脱敏交付物与质量门禁（TRACE 五维：真实/可查/准确/合规/证据）。

**本技能不做（Out，集中声明）**
1. 不出具任何监管认证、注册批准或合规承诺（结论≠监管放行）。
2. 不代为向监管方提交申报或应对飞检（仅提供支撑材料）。
3. 不臆断、不编造证据；未核验项列为缺口，不凭行业惯例补全。
4. 不保留可识别企业名/人名/证号/UDI 明文于对外交付物（默认脱敏）。
5. 不把草案/征求意见中的标准当正式结论依据。
6. 不接触、不存储用户平台凭据或机密系统访问权。

## 二、输入约束与输出承诺

**推荐问法**
- 标准情报：`整理 EU MDR 2017/745 与 FDA UDI 法规在可追溯性上的关键条款差异，给适用条款清单与最新动态简报（标注版本与查询日期）。`
- 追溯审计：`审计某植入类器械的 UDI 追溯体系：核对 UDI-DI/PI 赋码、上报 EUDAMED/GUDID 符合性、批次与供应链来源链路是否断链。`
- 体系审核：`按 ISO 13485:2016 与医疗器械 GMP，审计生产/检验/发运记录的可追溯性，输出差距分析与整改建议。`
- 白皮书：`把我们的供应链追溯方法论写成白皮书章节，含国际标准对标、验证方法与参考文献。`

**必填/建议字段引导**
- 受审对象（脱敏代称）、器械类型、适用标准范围。
- 三锚输入：UDI-DI/PI、序列号、批号（身份锚）；供应商资质、物料批号、设计开发文档（来源锚）；生产/检验/发运记录、投诉召回联动（行为锚）。
- 查询日期与标准状态（正式/草案/征求意见）。

**输出承诺**
- 适用条款清单（附版本与查询日期）。
- 三锚证据链记录（含断链/缺口记录）。
- 追溯审计报告（对象/范围/方法论/证据链/发现项/结论分级/整改建议）。
- 白皮书/技术报告章节（按需）；法规预警（按需）。所有交付物脱敏并过质量门禁。

## 四、常见错误与反模式

**反模式 1 ✗ 把审计结论当合规认证**
- 错误：对外写"本产品已通过 EU MDR/FDA 合规认证""审计结论即监管放行"。
- ✓ 替代：结论仅表示在所审范围内、基于所提供证据链的可追溯性审计判断（通过/有条件通过/不通过），不构成任何监管认证或合规承诺。

**反模式 2 ✗ 标准情报照搬、不标时效**
- 错误：复制条款原文或二手解读，不标版本、状态与查询日期，默认"一直有效"。
- ✓ 替代：引用前从发布机构一手来源核实，标注版本（如 ISO 13485:2016）、状态（正式/草案/征求意见）与查询日期；草案须显式标注非正式效力。

**反模式 3 ✗ 三锚只填两锚**
- 错误：身份/来源/行为三选二，缺锚仍以"证据完整"下结论。
- ✓ 替代：三锚缺一不可；任一锚无法采集须在报告中显式记录缺口，并据此下调结论等级，不隐瞒断链。

**反模式 4 ✗ 敏感数据写进公开报告**
- 错误：白皮书保留企业名、客户名、人名、UDI 明文、批号、证书编号。
- ✓ 替代：默认全量脱敏，用"企业A""批次X"代称，UDI 仅保留必要脱敏片段，发布前过质量门禁。

**反模式 5 ✗ 结论等级乱用**
- 错误：重大断链仍给"通过"，或轻微瑕疵给"不通过"，或用等级替代整改优先级。
- ✓ 替代：等级严格对应证据链完整性；等级与整改建议/优先级并列，互不替代。

**反模式 6 ✗ 用缺证推测补全证据链**
- 错误：三锚不足时以"行业通常如此"补全并下结论。
- ✓ 替代：证据以"已核验"为准，未核验项列为缺口，按第十章降级，不臆断。

**高频 Q&A**
- Q：和单次质量审计区别？A：三线协作端到端 SOP，产出带结论分级与整改建议的审计报告，而非单点检查表。
- Q：三锚审什么？A：身份锚审唯一标识一致性；来源锚审供应商资质/物料批号/设计开发文档链路连续性；行为锚审生产/检验/发运记录及投诉召回联动留痕。
- Q：标准会过时吗？A：线一"先查证后主张"，从一手来源核实并标时效与查询日期；区分正式/草案/征求意见。
- Q：结论等级？A：通过/有条件通过/不通过，须有证据支撑，不通过项附整改建议与优先级。
- Q：能直接用于注册申报或飞检？A：可作为支撑材料；最终对外提交以监管最新要求与责任主体确认为准，本团不做合规承诺。
- Q：敏感信息怎么处理？A：默认脱敏企业名/人名/证号；对外发布前过质量门禁。

## 五、标准 SOP

四阶段 SOP（三线串并行），**不许跳步**。

| 步 | 动作 | 产物 | 易踩坑 |
|----|------|------|--------|
| Phase1 标准依据核查（并行） | 调度线一，下发监管/标准上下文 | 适用条款清单 + 最新动态简报 | 凭记忆引条款；未标版本/状态/查询日期 |
| Phase2 三锚核验与证据链审计（串行） | 统筹线亲执行身份/来源/行为锚核验 | 三锚证据链记录（含断链/缺口） | 缺锚仍下结论；未标时效 |
| Phase3 报告成稿（串行） | 调度线二，结构化审计结论与证据链 | 审计报告/白皮书章节 | 引用不标版本条款；未脱敏 |
| Phase4 最终报告（统筹汇编） | 统筹线汇总定稿 | 结论分级 + 整改建议 | 结论与证据不匹配；漏局限声明 |

**三锚核验要点（核心审计）**
- 身份锚：确认"哪台/哪批器械"——UDI-DI/PI、序列号、批号、唯一标识与主体识别一致性。
- 来源锚：确认"从哪来、依什么标准"——供应商资质、物料批号、设计开发文档与来源链路连续性。
- 行为锚：确认"经历了什么、可溯"——生产/检验/发运记录，投诉/召回联动留痕。
- 顺序：采集三锚 → 核验凭证与来源链路 → 识别伪造/断链/不一致。结论分级：通过/有条件通过/不通过。

**审计报告模板骨架**
```markdown
# 追溯审计报告
## 1. 审计对象（脱敏代称/器械类型/范围）
## 2. 审计范围与方法（适用标准+版本+查询日期；四阶段SOP；信息时效）
## 3. 三锚证据链（身份/来源/行为锚核验结果；断链缺口记录）
## 4. 发现项（编号|发现|关联锚/条款|风险）
## 5. 结论等级（通过/有条件通过/不通过 + 依据）
## 6. 整改建议（优先级|建议|责任指向）
## 7. 局限声明（范围边界/未覆盖项/证据缺口/不构成合规认证）
```
**差距分析表头**：`标准条款 | 要求要点 | 受审现状 | 差距描述 | 风险等级 | 建议与优先级`

## 六、关键事实速查

- 标准依据一手来源（链接可达性一律**待核验**，以官方为准）：ISO、欧盟官方公报（EU MDR 2017/745）、FDA（QSR/UDI）、GS1、国家药监局等。
- 覆盖标准至少含：EU MDR 2017/745、FDA QSR 与 UDI 法规、ISO 13485、ISO 15223-1、IEC 62366、GS1 应用标准、MDSAP、医疗器械 GMP。
- 结论分级标尺：证据齐备且无断链=通过；存在可整改缺口=有条件通过；无法闭合断链或伪造=不通过。
- 标准可能修订：所有条款引用须标版本与查询日期；草案/征求意见内容不作为正式结论依据。
- 质量门禁 TRACE 五维：真实/可查/准确/合规/证据；对外交付物默认脱敏。

## 七、铁律（PROHIBITED 绝对禁止）

1. **结论绝不等于监管认证/合规承诺** —— 不得写"已通过 EU MDR/FDA 合规认证""审计即监管放行"。
2. **三锚缺一不可** —— 任一锚缺失或断链须显式记录并影响结论等级，不得隐瞒。
3. **绝不臆断或编造证据** —— 未核验项列为缺口；不以行业惯例或推测补全证据链。
4. **绝不把草案/征求意见当正式结论依据** —— 须显式标注非正式效力。
5. **绝不在对外交付物保留可识别敏感信息** —— 默认脱敏（企业名/人名/证号/UDI 明文）。
6. **绝不引用未核实的标准条款** —— 须标版本、发布状态与查询日期，结论以官方一手来源为准。
7. **绝不代行监管申报动作** —— 仅提供支撑材料，最终对外提交由责任主体确认。

## 八、输入输出依赖

- **依赖文件**：无强制外部脚本；本技能为流程型 SOP，纯文本/Markdown 产出。
- **依赖工具**：标准检索以发布机构官方来源为准（一手来源链接**待核验**）；如需结构化输出，用户侧 Markdown 编辑器即可。
- **环境/凭据**：本技能**不读取任何凭据**。如未来接入标准数据库 API，凭据从保险库 `~/.ucvault_local` 读取，**绝不**进入对话、代码或日志；当前版本标准核实由用户/责任主体从一手来源确认。
- **输入**：受审对象（脱敏）、三锚输入材料、查询日期与标准状态。
- **输出**：适用条款清单、差距分析、三锚证据链、审计报告、白皮书章节（按需）、法规预警（按需）。

## 九、示例

**示例 1：UDI 追溯审计**

- 加载：线一标准依据（Phase1）→ 线三三锚核验（Phase2）→ 线二报告成稿（Phase3）。

**示例 2：质量体系审核**
- 问题：按 ISO 13485:2016 与 GMP 审计生产/检验/发运记录可追溯性。
- 加载：Phase1 标准依据 → Phase2 三锚 → Phase3 报告。
- 答案框架：差距分析表（条款/要求/现状/差距/风险/建议）｜发现项表｜结论分级｜整改优先级。

**示例 3：标准情报对标**
- 问题：整理 EU MDR 与 FDA UDI 在可追溯性的关键条款差异。
- 加载：线一（Phase1）为主，调度对标简报。
- 答案框架：适用条款清单（版本+查询日期）｜关键要求对照｜对业务影响｜行动建议｜法规预警（草案标注）。

## 十、错误处理

本技能为流程型，无系统错误码；以下为异常场景降级与修正引导（约 6 类）。

| 错误码 | 现象 | 原因 | 修正引导 |
|--------|------|------|----------|
| E-STD-001 | 引用标准时效不明/草案当正式 | 未从一手来源核实 | 以发布机构一手来源为准并标注版本/状态/查询日期；草案单独标注，不作正式结论依据 |
| E-ANCH-002 | 三锚缺料/断链仍下"通过" | 输入不足或隐瞒缺口 | 暂停核验，输出"信息需求清单"逐锚补齐；缺口显式记录并下调结论等级 |
| E-SENS-003 | 对外内容含可识别企业名/人名/UDI明文 | 未脱敏 | 默认代称+脱敏片段；确需明文须另行确认授权，发布前过质量门禁 |
| E-SCOPE-004 | 请求超范围（非医械/代申报） | 偏离声明场景 | 回退至可追溯性审计范围内；超出部分告知不在职责内，建议责任主体/有资质机构处理 |
| E-CONCL-005 | 结论与证据不匹配（重大断链仍通过） | 执行偏离 SOP | 回到四阶段 SOP 重走，强制补齐三锚与时效；结论以重对齐证据链为准 |
| E-VER-006 | 未核验即主张标准条款 | 凭记忆/二手解读 | 标 [待核验] 或 [模型知识—需核验]；未调取原文不得补写条款号 |
