# 喂料工作流（Feeding Workflow）

> 配套专家：喂料专家（feeding-expert）。本技能是可执行的五步喂料流程 + 防编造纪律，配套模板见 `references/喂料包模板.md` 与全局纪律 `references/喂料纪律.md`。

## 定位

**何时用**：用户要把零散素材（文件/网址/贴文/会议记录/截图）加工成**已核实、可安全入库**的知识资产；要给多智能体团队/RAG/知识库备料；要溯源核实数值/条款/证号；要做防 AI 编造事实核查或发布前敏感信息扫描。

**何时不用**：
1. 纯闲聊、无需入库或溯源的随意提问。
2. 素材已确认可靠、无需再核实即可直接引用（仍建议三要素备查）。
3. 用户要求"直接编一个合理数字填进去"——本技能禁止推断填充。

## 一、能力边界（In/Out scope）

**本技能做（In）**
1. 收料登记：登记料源/格式/数量，建/更新喂料台账。
2. 溯源核实：逐条查官方源核实数值/条款/证号，每条标出处与核实日期。
3. 提炼原创化：第三方内容改写重组，区分公开区（可入库）与私密区（只留本地）。
4. 分区入库：落地知识库 references / RAG 补料区 / 喂料包容器，回写索引。
5. 回执：台账记一行 + 知会用户。

**本技能不做（Out / 明确禁止）**
1. ❌ 不镜像第三方原文、不标注第三方出处。
2. ❌ 不推断填充：查不到的数值/条款一律标"待核实"，禁止编造。
3. ❌ 不把私密区（客户/报价/真名笔记）写入公开知识库或发布包。
4. ❌ 不自动执行外部动作（入库云端/发布/外发）而无用户授权。
5. ❌ 不保证"喂料包没有的团队就一定不输出"——须派活 prompt 写死禁编造声明（见六）。

## 二、输入约束与输出承诺

**推荐问法**
- 「这批素材帮我整理入库，记得溯源核实数值」
- 「给 RAG 准备一份喂料包，凡带限值都要三要素齐全」
- 「这块知识缺口盘点一下，出个喂料清单」

**字段引导**
| 要素 | 是否必填 | 说明 |
|---|---|---|
| 料源 | 必填 | 文件/网址/贴文/会议记录/截图；注明来源性质（官方/非官方） |
| 入库目标 | 建议 | 知识库 references / RAG 补料区 / 喂料包容器 |
| 数值/条款 | 条件 | 凡带数值/限值/条款必须给三要素，否则标"待核实" |

**输出承诺**
- 每条带数值/条款的料：三要素齐全（出处+适用条件+归口标准）或显式"待核实"。
- 产出喂料包/入库索引 + 台账一行回执。
- 敏感信息扫描 0 命中才可发布/入库公开区。

**示例对话**
> 用户：甩来一条群聊贴文"某器械环氧乙烷残留限值是 X mg"，帮我进知识库。
> 技能：触发喂料 → 第一步收料登记（来源=群聊，非官方，标"待核实"）→ 第二步查 nmpa.gov.cn/GB/T 16886 核实 → 第三步原创化只留客观事实 → 第四步写喂料包三要素 → 第五步台账回执。

> 用户：这数字查不到，你帮我编个合理的填进去吧。
> 技能：拒绝。按七·2 禁止推断填充，标"待核实"，并在包外其他数字一律标"待核实"。

## 四、常见错误与反模式

**FAQ · 反模式（先写✗再写✓）**
- ✗ 反模式：贴文/聊天记录直接镜像原文入库，连第三方出处一起搬。
  ✓ 替代：经"溯源核实→提炼原创化"，只留公开客观事实，不标注第三方出处。
- ✗ 反模式：查不到的数值自己"编个合理值"补上。
  ✓ 替代：标"待核实"，禁止推断填充；喂料包外数字一律标"待核实"。
- ✗ 反模式：把客户名/报价当普通料写进公开知识库。
  ✓ 替代：归入私密区只留本地，永不进发布包/公开库。
- ✗ 反模式：跳过敏感扫描直接发布。
  ✓ 替代：真名/邮箱/手机号/本地路径/API 密钥/客户信息 6 类 0 命中才可发布。

**高频 Q&A**
- Q：什么算"已核实素材"？A：带数值/限值/条款的必须三要素齐全（官方源+日期、适用条件、归口标准），且来自 gov.cn/nmpa.gov.cn/ecfr.gov/eur-lex/iso.org/openFDA 等官方源；查不到一律标"待核实"。
- Q：贴文/聊天记录能直接入库吗？A：不能镜像原文，需溯源核实+原创化，区分公开区/私密区，第三方出处不标注。
- Q：为什么发布前必须敏感扫描？A：防真名/邮箱/手机号/本地路径/API 密钥/客户信息泄漏，0 命中才可发布。

## 五、标准 SOP

五步流程**固定顺序，不可跳步**：

| 步 | 动作 | 产物 | 易踩坑 |
|---|---|---|---|
| 1 | 收料登记：登记料源/格式/数量，建/更新喂料台账（对象×缺料×优先级×状态） | 台账更新 | 未记来源性质（官方/非官方） |
| 2 | 溯源核实：逐条查官方源核实数值/条款/证号，标出处+核实日期 | 核实结论 | 未查官方源就采信（反模式） |
| 3 | 提炼原创化：第三方改写重组，只留公开客观事实；区分公开区/私密区 | 原创化内容 | 镜像原文/标第三方出处 |
| 4 | 分区入库：落地 references/RAG 补料区/喂料包容器，回写索引 | 入库索引 | 私密区误入公开库 |
| 5 | 回执：台账记一行（喂了什么/核实到什么程度）+ 知会用户 | 回执 | 漏记台账 |

**防编造三要素（凡数值/限值/条款必备）**

| 要素 | 含义 | 示例 |
|---|---|---|
| 出处 | 官方来源 + 日期 | GB/T 16886.7-2015 |
| 适用条件 | 什么产品/市场/阶段 | 环氧乙烷灭菌器械 |
| 归口标准 | 哪个法规/标准体系管 | 生物相容性标准 |

- 官方源优先：gov.cn / nmpa.gov.cn / ecfr.gov / eur-lex / iso.org / openFDA。
- 查不到就标"待核实"，**禁止推断填充**。
- 喂料包写死声明："以下喂料包为唯一事实来源，包外数字一律标'待核实'"。

## 六、关键事实速查

- 敏感扫描 6 类（入库/发布前必做，0 命中才可发布）：真名 / 邮箱 / 手机号 / 本地路径 / API 密钥 / 客户信息；含命中的先脱敏或剔除。
- 分区规矩：公开区（法规知识/通用路径/官方链接）可入知识库、可随发布包分发；私密区（客户项目/报价/供应商/在职公司资料/真名笔记）只留本地，永不进发布包。
- 外部动作红线：入库云端知识库、发布、外发 = 外部动作，执行前必须逐次征得用户授权。
- 喂料包命名：`喂料包_主题_YYYYMMDD_vN.md`；模板结构见 `references/喂料包模板.md`（任务口径/事实料区/官方链接区/边界坑位/待核实区）。
- 全局纪律细则见 `references/喂料纪律.md`（五条铁律 + 分区规矩 + 外部动作红线）。

## 七、铁律（PROHIBITED 绝对禁止）

1. 禁止推断填充：查不到的数值/条款一律标"待核实"，不得编造。
2. 禁止镜像第三方原文、禁止标注第三方出处。
3. 禁止把私密区内容写入公开知识库或发布包。
4. 禁止未经用户授权执行外部动作（入库云端/发布/外发）。
5. 禁止漏做敏感扫描即发布/入库公开区。

## 八、输入输出依赖

- **模板/纪律文件**：`references/喂料包模板.md`（喂料包结构模板）、`references/喂料纪律.md`（全局五条铁律与分区规矩）。
- **输入**：用户提供的零散素材（文件/网址/贴文/会议记录/截图）及入库目标说明。
- **凭据**：本技能不依赖账号/密钥；若接入需鉴权的知识库/云存储，凭据一律从本地保险库 `~/.ucvault_local` 读取，绝不进对话/代码/日志。
- **输出**：喂料包/入库索引/喂料台账回执；私密区只留本地。

## 九、示例

**示例一：群聊贴文进知识库（完整五步）**
> 问题：群聊贴文"某器械环氧乙烷残留限值是 X mg"要进知识库。
> 加载：五 → ①收料登记（来源=群聊，非官方，标"待核实"）②查 nmpa.gov.cn/GB/T 16886 核实限值数字与适用条件 ③原创化只留"EO 残留限值 X mg（依据 GB/T 16886.x，适用于 XX 器械）" ④写喂料包三要素齐全，包外数字标"待核实" ⑤台账回执。
> 答案框架：入库一条三要素齐全的事实料 + 回执"已入库，限值 X，出处 GB/T 16886.x"；全程敏感扫描 0 命中。

**示例二：查不到的数值**
> 问题：这个限值网上查不到，帮我估一个填进喂料包。
> 加载：七·1 → 标"待核实"，禁止编造。
> 答案框架：该字段留"待核实"并标注缺失，不在包内填充推测值。

**示例三：含微信号的贴文**
> 问题：一条含微信号的行业贴文想发到对外知识库。
> 加载：六（敏感扫描）→ 命中微信号（手机号类）→ 先脱敏/剔除，0 命中才可发布。
> 答案框架：脱敏后发布，或归私密区只留本地。

## 十、错误处理

| 错误码 | 现象 | 原因 | 修正引导 |
|---|---|---|---|
| E001 | 数值无三要素 | 未溯源核实直接入库 | 回第二步查官方源补出处+适用条件+归口标准 |
| E002 | 推断填充 | 查不到自行编值 | 按七·1 改标"待核实"，禁止编造 |
| E003 | 镜像第三方原文 | 直接搬运 | 回第三步原创化改写，去第三方出处 |
| E004 | 敏感扫描未 0 命中即发布 | 漏扫描/未脱敏 | 补敏感扫描，命中先脱敏/剔除 |
| E005 | 私密区误入公开库 | 分区错误 | 移出公开库，归私密区只留本地 |
| E006 | 未授权外部动作 | 擅自入库/外发 | 按七·4 中止，补用户逐次授权 |
