# 定位

本技能是**项目规划方法论工具**，把经典项目管理三件套（WBS 工作分解结构 + CPM 关键路径法 + RACI 责任矩阵）整理为 AI 可直接照做的操作指引，帮用户把「一个模糊的项目想法」变成「可排期、可分工、可追踪」的结构化计划。

## 何时用
- 需要把项目拆成任务、估算工期、排定顺序。
- 需要明确「谁负责、谁拍板、咨询谁、知会谁」。
- 需要识别关键路径、判断哪些任务不能拖延。
- 需要输出 WBS 树 / 甘特图文本 / RACI 矩阵用于汇报或对齐。

## 何时不用
- 做医疗、法律、投资、财务合规等**专业判定**（本技能不提供此类建议）。
- 需要真正执行任务、派单、自动写代码（本技能只产出计划，不执行）。
- 纯日常待办（<5 个任务）用简单清单即可，不必上 WBS/CPM。
- 需要实时多人协同编辑（请用项目管理软件，本技能产出文本草稿）。

## 一、能力边界

**能提供**
- WBS 工作分解：把项目拆成阶段→可交付成果→工作包，给出层级编码。
- CPM 关键路径排期：正推/逆推计算 ES、EF、LS、LF、总浮动 TF，标出关键路径。
- RACI 责任矩阵：为每项任务指派 R/A/C/I 角色。
- 甘特图文本、里程碑清单、依赖关系与风险点提示。

**不能提供**
- 不替代项目经理的专业判断与组织决策。
- 不自动执行、不派单、不调用外部系统（纯方法论，无运行时）。
- 不做财务预算精算、人员编制决策、合同或法规判定。
- 不保证工期绝对准确——工期来自用户输入的估算，技能只做规则校验。

**适用规模**
- 适合 1–50 人、周期 ≤ 12 个月的中小项目。
- 超大/超长项目：建议先按里程碑切分为多个子项目再分别规划。
- 输入越完整（任务、依赖、工期、角色），输出越可靠；信息缺失时按第六章降级处理。

## 二、输入约束与输出承诺

**输入约束**
- 必需：项目目标与范围的一句话描述。
- 推荐：已知任务或阶段清单、各任务工期估算（理想/乐观/悲观均可）、角色/人员名单。
- 可选：任务间依赖关系、里程碑、资源限制、截止日期。
- 格式：自由文本、列表、表格均可；无需固定模板。

**输出承诺**
- 结构化 WBS 树（含层级编码与 100% 规则校验）。
- CPM 排期表：每项任务的 ES/EF/LS/LF/TF 与关键路径标注。
- RACI 矩阵：每项任务恰好 1 个 A（Accountable）。
- 排期建议与风险点（浮动为 0 或负的任务优先提示）。

**输出质量标准**
- 每个工作包满足「动词+名词」命名（如「设计数据库」而非「数据库」）。
- WBS 满足 100% 规则：覆盖全部范围内的交付物，无遗漏无冗余（MECE）。
- 关键路径上任务 TF=0；非关键任务标注可拖延空间。
- 每项任务有且仅有一个 A；不存在「全员 R」或「无人负责」。

## 三、触发场景

**意图表**

| 用户意图 | 典型触发词 | 对应动作 |
|---------|-----------|---------|
| 拆任务 | 项目怎么拆 / 工作分解 / WBS / 任务分解 | 生成 WBS 树 |
| 排工期 | 怎么排期 / 关键路径 / CPM / 多久能做完 | 计算 CPM 与关键路径 |
| 分责任 | 谁负责 / RACI / 责任矩阵 / 分工 | 产出 RACI 矩阵 |
| 出图 | 甘特图 / 里程碑 / 进度表 | 文本甘特图+里程碑 |
| 诊断 | 为什么延期 / 哪天必须交 / 风险在哪 | 浮动分析与风险提示 |

**示例对话**

> 用户：我要上线一个官网，大概要哪些任务、怎么排期？
> 技能：先按 WBS 拆成「需求→设计→开发→测试→上线」五阶段，再逐层分解工作包，之后做 CPM 正推逆推算出关键路径。请告诉我各阶段预计工期和依赖关系。

> 用户：开发和测试谁拍板？
> 技能：用 RACI——开发任务的 A 通常是技术负责人，测试任务的 A 是 QA 负责人；两者 R 不同、A 唯一，避免责任重叠。

> 用户：哪些任务不能拖？
> 技能：关键路径上 TF=0 的任务不能拖延（如「联调」「上线准备」），任一延误都会直接推后整体工期。

## 四、常见错误与反模式

**FAQ**

- Q：WBS 拆多细合适？
  A：到「工作包」层级即可，单包工期建议 ≤ 80 小时（约 2 周），再细就失去管理意义。

- Q：关键路径只有一条吗？
  A：不一定。并行路径 TF 都为 0 时存在多条关键路径；任一变动都影响总工期。

- Q：RACI 里一个人能兼多角色吗？
  A：可以（如某人既是 R 又是 C），但每个任务**必须且仅有一个 A**。

- Q：工期估不准怎么办？
  A：用三点估算（乐观/理想/悲观），技能按你给的数字计算，不准确由估算本身决定，技能只校验规则。

**高频反模式（应避免）**
- ❌ 把「部门/角色」当 WBS 节点（WBS 拆的是「交付物/工作」，不是组织结构）。
- ❌ 工作包命名用名词无动词（无法判断要做什么）。
- ❌ 关键路径手动指定而非计算（必须以 TF=0 推导）。
- ❌ RACI 全填 R（无人拍板）或全填 C（无执行者）。
- ❌ 跳过依赖直接排并行（必须先定前置关系再算 CPM）。

## 五、标准 SOP

| 步骤 | 动作 | 产出 |
|-----|------|-----|
| 1. 定范围 | 澄清项目目标、交付物、截止日 | 范围一句话 |
| 2. 建 WBS | 逐层分解到工作包，编层级码 | WBS 树（100% 规则校验） |
| 3. 排依赖 | 标每项任务的前置/后置关系 | 依赖网络 |
| 4. 估工期 | 给每项任务工期（三点更佳） | 工期表 |
| 5. 算 CPM | 正推求 ES/EF，逆推求 LS/LF，算 TF | 排期表+关键路径 |
| 6. 填 RACI | 为每项任务指派 R/A/C/I | 责任矩阵 |
| 7. 出图 | 文本甘特图+里程碑+风险点 | 可读计划草稿 |
| 8. 校验 | 查 100% 规则、唯一 A、TF=0 路径 | 一致性核对 |

## 六、关键事实速查

- **WBS 100% 规则**：WBS 包含且仅包含范围内 100% 的工作，不漏不冗余。
- **80 小时规则**：单工作包工期 ≤ 80 小时，过细难管理。
- **MECE**：分解应相互独立、完全穷尽。
- **CPM 正推**：ES = max(前置 EF)；EF = ES + 工期。
- **CPM 逆推**：LF = min(后置 LS)；LS = LF − 工期。
- **总浮动 TF** = LS − ES = LF − EF；关键路径 TF = 0。
- **自由浮动 FF** = min(后续 ES) − EF。
- **RACI**：R 执行 / A 问责（唯一）/ C 咨询 / I 知会。
- **甘特图**：横轴时间、纵轴任务、条长=工期、连线=依赖。

## 七、铁律（PROHIBITED）

- 禁止输出医疗、法律、投资、财务合规等**专业判定或保证**。
- 禁止编造工期、依赖或角色——所有数字须来自用户输入或明确标注为假设。
- 禁止跳过重算直接「指定」关键路径；必须以 TF=0 推导。
- 禁止出现「无 A」或「多 A」的任务（每项任务恰好 1 个 A）。
- 禁止把部门/角色当作 WBS 分解节点。
- 禁止声称本技能会替你执行任务、派单或保证项目按时交付。
- 禁止把治理/溯源声明当作功能承诺写入方法论正文。

## 十、错误处理

| 异常 | 识别信号 | 处理 |
|-----|---------|------|
| 输入不足 | 缺范围或无任务清单 | 先问清范围与已知任务，再继续；不臆造 |
| 循环依赖 | A 依赖 B、B 又依赖 A | 指出环路，请用户拆断或重排顺序 |
| 缺失 A | 某项任务无 Accountable | 提示补一个唯一 A，拒绝输出无 A 矩阵 |
| 工期冲突 | EF 超过截止日 | 标红超期路径，建议压缩关键路径或加资源 |
| 估算缺失 | 任务无工期 | 用三点估算模板请求补充，或标注为假设值 |
| 规模超限 | 任务数/周期远超适用规模 | 建议按里程碑拆分为多个子项目 |
| 误用请求 | 要求医疗/法律/投资判定 | 礼貌拒绝并指向免责声明，不提供该类结论 |

> 所有错误均向用户给出**可执行的修复建议**，而非仅免责声明。
