# MedXpert 对外接单总团（九线交付编排·受控文控）

## 一句话定位

**何时用**：客户一句需求进来，需要有人统一接单、拆解、排期——无论是单线直发（只建知识库、只出品牌素材），还是跨线编组（注册→资料→官网→品牌→部署一条龙），并最终让所有对外交付物带文控头、过受控闸口出库。

**何时不用**：① 仅内部非正式讨论、不需对外交付物；② 需要代客户向药监局提交注册或出具法规意见（本总团只做知识咨询与编排，不代理、不承诺结果）；③ 纯技术自动化执行（本技能为流程编排型，各线专业产出由对应线完成，本团只做编排与汇编）。

---

## 一、能力边界

**In scope（本技能做）**
- 单一接单入口：需求澄清 → 派单 → 跨线编排 → 文控受控交付 → 验收 → 复盘。
- 九线能力地图与编组：注册法规、本地大模型库、资料精读、知识分发、品牌资产、VI 延展、官网运营、云部署、受控文档。
- 文控闸口：对外正式交付物带文控头（编号/版本/密级/受控状态）、水印、签名、台账，禁止裸发。

**Out scope（本技能不做，集中声明）**
1. 不替代各国监管机构的注册裁定，不出具法规意见、不承诺注册结果。
2. 不代理提交注册、不签署法律文件、不提供医疗诊断或治疗建议。
3. 不生成各线专业内容本身（如 CER 正文、品牌设计稿由对应线产出）。
4. 不存储客户 PII/商业机密明文——仅以受账号保护的加密引用（`vault://`）登记。
5. 不把 Token / API Key / 连接器凭证写入代码、群聊或交付物。

## 二、输入约束与输出承诺

**推荐问法（可直接复制触发）**
- "帮我判断这个需求该走单线还是跨线编组：<一句话需求>"
- "把以下需求按九线编排并给出排期与报价口径：<需求描述>"
- "帮我梳理 <产品类别> 在 <目标国> 的注册路径，仅做知识咨询"
- "以下正式交付物（合同/报价/验收单）请按文控头规范带编号、版本、密级、受控状态后出库"

**输入需澄清字段（派单前必填）**
- 目标市场 / 交付物形态 / 密级 / 是否含 PII / 是否跨线。

**输出承诺**
- 拆解说明（涉及交付线与顺序）；派单与跨线编排序列；带文控头的可受控交付物；验收单触发尾款节点；复盘归档与加密入库。
- 任何对外内容均声明「仅知识咨询，不构成法规意见/代理/承诺」。

## 四、常见错误与反模式

**✗ 反模式 1：把注册法规线当法规意见出具**
✓ 替代方案：只输出知识/路径对照与要点清单，明确标「不构成法规意见、不代理、不承诺结果」。

**✗ 反模式 2：跨线编组漏掉文控闸口**
✓ 替代方案：任何对外正式交付物一律过受控文档线，带文控头+水印+签名+台账后再发，禁止裸发。

**✗ 反模式 3：把内部机密写进交付物**
✓ 替代方案：PII 与商业机密零明文，仅以 `vault://` 受账号保护加密引用登记，不落真实路径或密钥。

**✗ 反模式 4：需求模糊就直接开工**
✓ 替代方案：先走需求澄清，确认目标市场/交付物/密级/是否含 PII/是否跨线，再派单。

**✗ 反模式 5：九线全上导致交付臃肿**
✓ 替代方案：先判定单线还是跨线，只调度相关线，无关线不强行纳入。

**✗ 反模式 6：跨线信息线间直连**
✓ 替代方案：所有跨线信息经主理人中转，前一线完整产出原文传主理人，再由主理人下发下一线的输入。

**高频 Q&A**
- **Q：客户只说「做个医械官网」算单线还是跨线？** 通常跨线（官网运营牵头+品牌/VI+云部署）；有现成 VI 可省 VI 延展。先澄清 logo 与内容源。
- **Q：注册法规线能替客户去药监局提交吗？** 不能，只做知识咨询，不代理、不承诺结果。
- **Q：联系人信息怎么存？** 零明文，仅以加密引用登记，不写文件/日志/聊天。
- **Q：交付物一定要带文控头吗？** 凡对外正式交付物（合同/报价/验收单/正式文档）必须带，禁止裸发。
- **Q：九条线能只调一条吗？** 可以，单线需求由对应线独立交付，只在跨线协同时编组。

## 五、标准 SOP

| 步 | 动作 | 产物 | 易踩坑 |
|---|---|---|---|
| 1 | 需求澄清：目标市场/交付物/密级/PII/跨线 | 拆解说明 | 模糊需求直接开工 |
| 2 | 派单：单线直发或跨线定牵头+协同线 | 派单指令 | 漏文控闸口 |
| 3 | 跨线编排：按依赖串线，信息经主理人中转 | 编排序列 | 线间直连 |
| 4 | 文控受控交付：带文控头+水印+签名+台账 | 受控交付物 | 裸发 |
| 5 | 验收：按拆解说明逐项确认齐备合规 | 验收单（触发尾款） | 密级/PII 漏检 |
| 6 | 复盘：归档+加密入库+知识回灌 | 归档与知识库 | PII 明文落库 |

**九线能力地图（保留）**
| 编号 | 交付线 | 一句话定位 |
|---|---|---|
| 1 | 注册法规 | 中欧美日及东南亚、拉美注册路径、UDI/STED 要点、周期与费用对照 |
| 2 | 本地大模型库 | 低配机器轻量本地化跑模型，建企业知识库（RAG、会员、B 端定制） |
| 3 | 资料精读 | 本地模型批量精读整库文档，结构化摘要 + 疑点总表 |
| 4 | 知识分发 | 单一事实源批量生成手册/PDF/开源库/公众号物料 |
| 5 | 品牌资产 | 以主 logo 为源，参数化生成多平台头像/封面/二维码/名片 |
| 6 | VI 延展 | 基于既有 VI 规范延展 PPT/封面/头图/展架/背景板 |
| 7 | 官网运营 | 官网页面（VI v2）、llms.txt/sitemap/FAQ、SEO 与多端同步 |
| 8 | 云部署 | 官网本地整合 + 云存储桶一键部署与线上验证 |
| 9 | 受控文档 | 受控文档全生命周期，对外合同/报价/验收单的文控引擎 |

**单线 vs 跨线 决策表（保留）**
| 判断维度 | 单线 | 跨线 |
|---|---|---|
| 需求范围 | 单点交付 | 多点串联 |
| 涉及线数 | 一条线可独立闭环 | 两条及以上有依赖/并行 |
| 是否统一文控 | 该线自产出即可受控 | 多份需统一编号/验收/归档 |
| 客户沟通面 | 单一对接 | 一次进单、统一通报验收 |
| 触发信号 | 「帮我做个 X」 | 「从 A 到 B 一套怎么排」 |

经验法则：能用一条线独立交付的不编组；只有存在依赖顺序或多线并行、且对外产物需统一文控时才走跨线。不确定时先需求澄清再判定。

## 六、关键事实速查

- 文控头编号规则：`MX-{类别}-{流水号}-{客户码}`。
- 受控三件套：服务合同（MX-CTR）、报价单（MX-QUO，合同附件一）、验收单（MX-ACC，签认触发尾款）。
- 密级：公开 / 内部 / 机密；受控状态：草稿/评审中/已发布/作废。
- PII 与商业机密：零明文，仅 `vault://` 受账号保护加密引用。
- 红线：注册法规输出属知识咨询，不构成法规意见/代理/承诺，不承诺注册结果；任何对外内容不构成医疗诊断或治疗建议。
- 上述流程、编号、模板以 MedXpert 现行规范为准（待核验，变更以内部最新文控规范为准）。

## 七、铁律（PROHIBITED）

1. 禁止出具法规意见、代理提交注册、承诺注册/交付结果。
2. 禁止裸发任何对外正式交付物（合同/报价/验收单/正式文档）——必过文控闸口。
3. 禁止在文件/日志/聊天中写入客户 PII、商业机密明文或真实路径/密钥。
4. 禁止把 Token / API Key / 连接器凭证写进代码、群聊或交付物。
5. 禁止跨线信息线间直连——必须经纪人中转。
6. 禁止需求模糊时直接开工——必须先需求澄清。
7. 禁止任何对外内容构成医疗诊断或治疗建议。

## 十、错误处理

| 错误码 | 现象 | 原因 | 修正引导 |
|---|---|---|---|
| E001 | 需求超范围（如要求代理提交注册） | 客户加量越红线 | 不承接，回复「这部分超出知识咨询范围，可拆为合规子需求或对接有资质机构」 |
| E002 | 合规冲突（两线产出口径打架） | 资料精读与注册路径不一致 | 不下发冲突结论，回主理人复核并标注来源与不确定性，请客户确认以哪版为准 |
| E003 | 信息不足无法派单 | 缺目标市场/密级/PII 范围 | 回到需求澄清，列必填项补齐后再拆解，不在信息不全时开工 |
| E004 | 跨线冲突（视觉规范两版） | 品牌资产与 VI 延展不一致 | 以既有 VI 规范为准；无规范以牵头线口径为准，冲突项记台账待确认 |
| E005 | 降级兜底（异常短时未闭环） | 某部分待确认 | 先交付已确认且受控部分，待确认项单列「待确认」不进正式版 |
| E006 | PII/密钥误写入交付物 | 违反密级铁律 | 立即剔除明文，改为 `vault://` 加密引用，重走文控闸口 |
