# local-llm-eval-assist（本地 LLM 自评辅助）

**定位**：一个"让 AI 给自己打分但尽量不虚高"的方法论 + 可执行 SOP 工具。核心是用**本地部署的 LLM**（如 Ollama 上的 qwen2.5 / llama3）对产出物（文档、代码、能力指数、学习成果）做机器评分，并与人工基线分对照，生成**校准分**，从而对抗两类偏差：

- **Goodhart 效应**：当"分数"成为目标，指标会被优化成失真（为了高分而高分）。
- **乐观偏差**：人对自己的产出普遍自评偏高（Dunning-Kruger 同源现象）。

**何时用**：
- 想对某项能力/产出做可重复、可审计的量化自评。
- 进化周评估、学习效果打分、文档/代码质量自检、能力指数自评。
- 需要**离线、数据不出本机**的评分（隐私敏感场景）。

**何时不用**：
- 需要权威第三方认证或合规强制评估（本工具是辅助自评，非认证）。
- 任务无明确可评分 rubric（先去定义标准，再来评分）。
- 纯主观、无客观依据的美学/创意判断（机器分仅作参考）。

## 一、能力边界

| 维度 | 支持 | 不支持 |
|------|------|--------|
| 评分对象 | 文本/代码/结构化产出、能力指数、学习成果 | 实时交互行为、物理世界操作 |
| 运行环境 | 本地 Ollama（离线，数据不出机） | 联网大模型代打分（会泄露数据，违背设计初衷） |
| 评分性质 | 辅助自评 + 偏差校准 | 权威认证、法律/医疗/财务结论 |
| 输出形式 | 分数 + 偏差分析 + 校准建议 + 存证记录 | 自动改写产出物（本工具只评不改） |

**明确不说**：本工具**非医疗器械、非医疗软件、无任何疗效或临床声明**；提及的治理框架（AI 护照、A³ 法则、XCGS）仅为溯源背景，不构成法规建议。

## 二、输入约束与输出承诺

**输入约束**
- 必须提供：①待评产出物（文本/路径/数据）；②**rubric（评分标准）**，含维度与分值区间。
- 可选：人工**基线分**（若有则进入三数对照）、期望语言。
- 拒绝：空内容、无 rubric、要求代写/代改产出物、要求联网调用远端模型。

**输出承诺**
- 固定返回四部分：**机器分**（按 rubric）、**偏差分析**（vs 基线分）、**校准分**（建议值）、**存证摘要**（三数 + 时间戳 + 模型指纹）。
- 所有评分**可追溯**：记录所用模型、prompt 版本、rubric 版本。
- 不编造分数、不隐瞒偏差；当机器分与基线分差距过大时，**显式告警**而非取均值掩盖。

## 四、常见错误与反模式（FAQ + 高频 Q&A）

**FAQ**
- **Q：自己给自己打分不会虚高吗？** A：会，这正是本工具要对抗的。机器分提供独立视角，校准分强制暴露偏差，不主张"信自己"。
- **Q：一定要本地模型吗？** A：设计上必须本地（Ollama），否则数据出机且评分受远端策略影响，违背"可审计、隐私"前提。
- **Q：机器分低就说明我差？** A：不一定。机器分按 rubric 机械执行，可能漏判隐性价值；校准分才是综合判断，且会标注不确定区间。

**高频 Q&A / 反模式**
- ❌ 反模式：只用机器分当结论 → ✅ 必须三数对照。
- ❌ 反模式：为拿高分反过来改产出物迎合 rubric（Goodhart）→ ✅ rubric 应在评分前冻结。
- ❌ 反模式：拿本工具做医疗/法律结论 → ✅ 仅限辅助自评，超出边界拒答。

## 五、标准 SOP（步骤表）

| 步 | 动作 | 产物 | 命令/模板 |
|----|------|------|-----------|
| 1 | 定义并**冻结** rubric | `rubric.md`（维度+权重+区间） | 人工确认 |
| 2 | 人工给出基线分 | `baseline_score` | 自评填写 |
| 3 | 本地模型出机器分 | `machine_score` | 见下 Ollama 调用 |
| 4 | 偏差分析 | `delta = machine - baseline` | 公式自动 |
| 5 | 生成校准分 | `calibrated_score` | 规则 + 告警 |
| 6 | 写存证 | `eval_record.json` | 含模型指纹+时间戳 |

**Ollama 调用（本地，离线）**
```bash
# 确保本地已启动 Ollama 且拉取模型
ollama pull qwen2.5:7b
curl http://localhost:11434/api/generate -d '{
  "model": "qwen2.5:7b",
  "prompt": "按以下 rubric 对文本打分，仅输出 JSON {维度:分数}：<RUBRIC>\n文本：<TEXT>",
  "stream": false
}'
```

**评分 Prompt 模板**
```
你是严格评分员。rubric：{{rubric}}。
待评文本：{{text}}。
要求：逐维度给分（0-100），输出 JSON，不解释。
```

## 六、关键事实速查

- **三数**：基线分（人工）/ 机器分（本地LLM）/ 校准分（综合）。
- **核心偏差**：Goodhart 效应、乐观偏差。
- **默认模型**：Ollama `qwen2.5:7b` 或 `llama3`，可替换。
- **端口**：本地 `http://localhost:11434`。
- **数据**：全程离线，不出本机。
- **存证**：`eval_record.json`（模型+prompt版+rubric版+时间戳）。
- **适用**：能力指数自评 / 进化周评估 / 学习效果 / 文档代码自检。
- **禁区**：医疗/法律/财务结论、联网代打分、代写代改。

---

## 七、铁律（PROHIBITED）

1. 禁止将评分结果包装为**权威认证/医疗/法律/财务结论**。
2. 禁止**联网调用远端模型**打分（破坏隐私与可审计前提）。
3. 禁止为迎合高分**回改产出物**（Goodhart）。
4. 禁止**只报机器分**而无三数对照与偏差说明。
5. 禁止**编造分数或隐瞒偏差**；差距过大必须告警。
6. 禁止把凭据/密钥写进对话或评分记录明文。
7. 禁止在 rubric 未冻结时即评分。

## 八、输入输出依赖（凭据从保险库读，不进对话）

- **模型端点配置**（如 Ollama 地址、模型名）：从本地环境变量 / 保险库读取（如 `OLLAB_URL`），**绝不**在对话中粘贴密钥或路径明文。

- **外部依赖**：仅本地 Ollama 进程；无第三方 API、无网络外发。
- **读取原则**：任何敏感配置一律"保险库 → 环境变量 → 脚本"，对话层只传"已脱敏的模型名/端口状态"，原始凭据不进入上下文。

## 九、示例

**输入（脱敏）**
```
rubric：结构40 / 信息密度30 / 可执行性30
基线分：85（用户自评）
文本：「本周完成 X 模块，梳理了流程，待优化项 2 条……」
模型：qwen2.5:7b（本地）
```

**输出**
```json
{
  "machine_score": {"结构": 78, "信息密度": 70, "可执行性": 60, "合计": 70.4},
  "baseline_score": 85,
  "delta": -14.6,
  "calibrated_score": 74,
  "alert": "机器分显著低于基线分(Δ=-14.6)，存在乐观偏差，建议复核「可执行性」维度。",
  "evidence": {"model": "qwen2.5:7b", "prompt_ver": "v1.1", "rubric_ver": "v1", "ts": "2026-09-01T20:07:00+08:00"}
}
```

**解读**：校准分 74 介于两者之间并向下修正，明确提示用户在"可执行性"上自评偏高。

## 十、错误处理

| 异常 | 检测 | 处理 |
|------|------|------|
| 无 rubric | 步骤1 缺失 | 中止，提示「请先定义并冻结 rubric」 |
| 本地 Ollama 未起 | `curl` 连接失败 | 提示启动命令 `ollama serve` / `ollama pull` |
| 模型返回非 JSON | 解析失败 | 重试1次；仍失败则返回原始文本并标 `parse_error` |
| 基线分缺失 | 步骤2 空 | 仅出机器分，标注「待补基线分以校准」 |
| Δ 超限（|Δ|>20） | 偏差过大 | 触发强告警，建议人工复核而非自动取均值 |
| 输入含密钥 | 正则命中 | 脱敏后处理，拒绝将明文写入存证 |

> 所有错误均返回**结构化错误信息 + 可操作下一步**，不静默失败、不编造分数。
