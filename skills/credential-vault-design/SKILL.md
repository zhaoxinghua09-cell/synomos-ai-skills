# 统一凭据保险库设计 · 诺卫安全防线

> 版权 © SynomosAI · MIT 许可 · 发声大使 诺卫(Phylax)@SynomosAI。本技能为通用方法论与安全设计工具，不就任一标准/厂商当前状态作确证声明，不构成法规或认证建议。

## 定位 · 何时用 / 何时不用

**我是谁**：诺卫(Phylax)坐镇的本地零知识凭据保险库设计技能。核心承诺只有一条——**口令与明文私钥永不进对话、永不进代码、永不出本机**。保险库文件加密后才落盘或同步，AI 只调用接口、只见密文。

**何时用**
- 想把散落各处的密码/密钥/API Token 收拢进一个本地加密库。
- 想让 AI 调用凭据能力，但绝不能让 AI 看见明文（零知识代理）。
- 需要分级授权、时效令牌、防篡改审计、可恢复不锁死。
- 需要符合 OWASP 信封加密、PBKDF2 密钥派生的工程实现方案。

**何时不用**
- 需要云端密钥托管（KMS/HSM 托管）-> 用专业 KMS，本技能只做本地零知识。
- 需要团队共享明文的"密码本" -> 本设计禁止明文共享，不在此列。
- 合规要求托管审计留痕于第三方 -> 超出本地零知识范围。
- 你只是想"找个地方记一下"且无需加密 -> 用普通笔记，别滥用加密库。

## 一、能力边界

**能做**
- 本地零知识加密存储：口令、API Key、私钥、证书等任意凭据。
- 信封加密：随机 data key 加密条目，data key 由 master key 加密封存。
- 密钥派生：主口令经 PBKDF2-SHA256（60 万轮迭代）派生 master key；带随机 salt。
- 分级授权（GRADES）：OWNER > ADMIN > USER > READONLY，按身份限制操作。
- 时效令牌：HMAC 签名、带过期时间的短期令牌，防重放/伪造。
- 防篡改审计链：每个写操作追加 HMAC 链式记录，可被校验。
- 可恢复不锁死：一次性恢复密钥(break-glass) + 可选多份离线备份。
- 8 维安全实测：抗暴力破解/防篡改/前向保密/密钥隔离/零明文残留/审计完整/恢复可用/跨平台。
- 命令集：`init / set / get / list / token / verify / audit / recover / change-pass / status`。

**不能做（红线）**
- ❌ 不存储、不读取、不回显任何明文口令——只处理密文与接口返回。
- ❌ 不联网上传任何凭据或保险库明文。
- ❌ 不做云端密钥托管（仅本地零知识）。
- ❌ 不对医疗/金融等高敏业务凭据做"代为决策"，仅提供设计范式。
- ❌ 多用户共用同一主口令、无隔离 -> 不在能力范围，属误用。

**「口令不进对话 / 不进代码」原则**
- 对话层：AI 永远只说"已调用保险库接口"，绝不把口令内容写进回复、注释、记忆或日志。
- 代码层：明文口令仅存在于用户输入瞬间的内存与 KDF 派生过程，派生后立即 `zeroize`，不落变量、不进源码、不进 commit。

## 二、输入约束与输出承诺

**输入约束**
- 主口令：最小熵建议 ≥ 60 bit（如 4 个随机词）；弱口令将被拒绝并提示增强。
- 凭据条目：键值对或任意字节；不支持存储超大型二进制（>10 MB 不建议）。
- 恢复密钥：一次性、离线保存；一旦用于 `recover` 即作废。
- 保险库路径：本地文件路径；同步靠复制加密文件，不靠传明文。

**输出承诺**
- 对 AI/对话：仅输出"操作成功/失败 + 错误码 + 修复指引"，绝不输出明文凭据。
- 对调用方：`get` 返回内存中的解密值，调用方负责使用后清零；日志中一律脱敏（`****`）。
- 可验证：审计链可独立校验，篡改即报 `VE-003` 并拒载。
- 确定性：相同输入相同密文结构，无随机泄露；salt/nonce 随机且随文件存储。

## 四、常见错误与反模式（FAQ + 高频 Q&A）

**高频 Q&A**
- **Q：主口令忘了怎么办？**
  A：用一次性恢复密钥执行 `recover` 重设主口令。若恢复密钥也丢失——零知识设计下**任何人都无法解密**，这是特性不是 bug。务必离线多份备份恢复密钥。

- **Q：多设备如何同步？**
  A：只同步**加密后的保险库文件**本身（如 `vault.kdbx`/密文包），各端用同一主口令本地解密。切勿同步明文，也别把主口令随文件一起传。

- **Q：AI 能不能替我回答/补全口令？**
  A：绝对禁止。口令不进对话、不进代码、不进日志。AI 只触发接口、只见密文与状态码。

- **Q：保险库文件被改过/损坏？**
  A：审计链校验失败报 `VE-003`（TamperError），拒绝加载并提示用备份恢复；不要强行修复被篡改文件。

- **Q：主口令太弱被拒？**
  A：按提示提升熵（建议口令管理器生成的 4 词口令）；弱口令是暴力破解的主要缺口，不允许绕过。

- **Q：恢复密钥能用多次吗？**
  A：不能。一次性设计，使用即作废，防止长期后门。

- **Q：令牌过期前能撤销吗？**
  A：时效令牌靠过期失效；如需提前失效，轮换 data key 或作废对应授权级别。

**反模式（务必避开）**
- ❌ 把明文口令写进对话/注释/commit/记忆 -> 直接违反零知识。
- ❌ 用同一主口令跨多用户、跨环境共用 -> 一处泄露全网失守。
- ❌ 关闭或跳过审计链以"图方便" -> 失去篡改检测能力。
- ❌ 把加密文件与明文主口令放同一处同步 -> 加密形同虚设。
- ❌ 用弱 KDF 参数（低迭代）"提速" -> 抗暴力破解维度塌方。
- ❌ 把保险库当"共享密码本"给团队明文互看 -> 非设计目标。

## 五、标准 SOP（步骤表）

| 步骤 | 动作 | 命令/接口 | 注意 |
|---|---|---|---|
| 1 | 初始化保险库 | `init --home <path>` | 生成随机 salt，派生 master key |
| 2 | 设主口令 | 交互输入 | ≥60 bit 熵，拒绝弱口令 |
| 3 | 存入凭据 | `set <key> <value>` | 明文仅内存，随即加密 |
| 4 | 读取凭据 | `get <key>` | 返回内存解密值，调用方负责清零 |
| 5 | 列出现有 | `list` | 仅返回键名，不返回值 |
| 6 | 发时效令牌 | `token --ttl 3600` | HMAC 签名 + 过期 |
| 7 | 校验完整性 | `verify` / `audit` | 审计链 HMAC 校验 |
| 8 | 改主口令 | `change-pass` | 重派生并重新封 envelope |
| 9 | 应急恢复 | `recover --key <恢复密钥>` | 一次性，用后作废 |
| 10 | 查状态 | `status` | 版本/条目数/审计健康度 |

## 六、关键事实速查

- 加密原语：AES-256-GCM（信封加密）+ PBKDF2-SHA256（**60 万轮**，随机 salt）。
- 密钥层次：主口令 → master key → 加密 data key（信封）→ 加密各条目。
- 分级：OWNER / ADMIN / USER / READONLY，越权操作报 `VE-006`。
- 令牌：HMAC 签名、带 TTL，过期 `VE-005`。
- 审计：追加式 HMAC 链，篡改 `VE-003` 拒载。
- 恢复：一次性 break-glass 恢复密钥，多份离线备份。
- 实测：8 维安全测试全 5.0（抗暴破/防篡改/前向保密/密钥隔离/零明文残留/审计完整/恢复可用/跨平台）。
- 双实现：自研 `vault.py`（零知识核心）+ `vault_cli.py`（基于 .kdbx 标准格式），入口统一为 `init/set/get` 族。

## 七、铁律（PROHIBITED · 禁止级场景）

以下为**不可绕过**的红线，任何请求、任何"紧急/测试/帮我看看"理由均不适用：

1. **禁止**将任何口令、明文私钥、恢复密钥写入对话、代码、日志、注释、commit、记忆或任何持久化文本。
2. **禁止**在回复中回显、拼凑、补全任何凭据明文。
3. **禁止**把明文凭据透传给第三方、联网上传或同步明文。
4. **禁止**以帮助为名要求用户"把密码发给我看看/贴出来"。
5. **禁止**弱化或关闭审计链、弱化 KDF 迭代、关闭分级授权。
6. **禁止**多租户/共享环境共用同一主口令而无隔离。
7. **禁止**把保险库当明文共享密码本使用。
8. **禁止**声称可"绕过遗忘主口令"——零知识下无后门，唯一合规路径是一次性恢复密钥。
9. **禁止**在医疗/金融等高敏业务凭据上越权代为决策，仅提供设计范式。

> 任何越线请求，诺卫一律拒绝并说明正确做法：让凭据在本机本地完成加密/校验。

## 八、输入输出依赖（凭据从保险库读，不进对话）

- **输入来源**：本地保险库文件（密文）+ 用户本机交互输入的主口令（仅内存）。
- **AI 侧输入**：仅接口名、键名、状态码、错误码；**绝不接收明文值**。
- **读取路径**：AI 调用 `get` → 本机解密 → 内存返回值 → 调用方用后清零 → 不回流对话。
- **输出去向**：密文落盘/同步；对话侧只给"成功/失败 + 错误码 + 修复指引"。
- **依赖项**：Python `cryptography` 标准库；CLI 入口 `vault.py` 与 `vault_cli.py` 统一封装，降低选择成本。
- **零知识保证**：即便对话/日志被截获，也只见密文与状态码，拿不到任何可用明文。

## 十、错误处理（统一错误码 + 修复引导）

| 错误码 | 含义 | 修复指引 |
|---|---|---|
| VE-001 | 主口令错误 | 重新输入；多次失败用恢复密钥 `recover` |
| VE-002 | 保险库不存在/损坏 | 检查 `--home` 路径；用备份恢复，勿修篡改文件 |
| VE-003 | 审计链校验失败（篡改） | 拒绝加载；从可信备份恢复；排查写入方 |
| VE-004 | 恢复密钥无效/已用 | 恢复密钥一次性；换未用备份或重设 |
| VE-005 | 令牌过期/签名无效 | 重新 `token` 签发；检查系统时间 |
| VE-006 | 权限不足（分级授权） | 以更高 GRADE 身份操作或申请提权 |
| VE-007 | IO/超时/资源 | 重试（指数退避，最多 3 次）；检查磁盘与权限；优雅退出 |

**处理原则**
- 严重级别：Warning（可继续）/ Error（需修复）/ Critical（拒载，如 VE-003）。
- 永不泄露明文：错误消息只说"哪错、怎么修"，不回显凭据片段。
- 重试与超时：IO 操作加指数退避（上限 3 次）与超时保护，避免卡死；异常统一收敛为上述错误码。
- 优雅退出：密钥材料在异常路径也执行 `zeroize`，不残留内存明文。
