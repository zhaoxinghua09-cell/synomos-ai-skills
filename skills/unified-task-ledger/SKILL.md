# 统一任务账本 unified-task-ledger

## 定位（一句话）

把「散落在各渠道、各 agent 的任务」收敛进**一本账**：统一编号、统一状态、统一收口，让人随时回答「派出去的任务现在什么状态」和「批量派单怎么统一收口」。

### 何时用它 ✅

- 一次指令要派发**多个**子任务给不同执行体，需要统一追踪与汇总。
- 需要跨渠道（直派 / 队列）核对「有没有漏派、有没有重派、卡在哪」。
- 需要向人汇报任务总进度、阻塞点、验收结论。

### 何时不用它 ❌

- 单条一次性指令、无需追踪状态 → 直接执行即可。
- 纯计算 / 纯检索，无「派单—回收」生命周期 → 用对应专项技能。
- 需要真实外部系统写操作（如真正调用 API 派单）→ 本技能只做**账本编排与对账**，实际执行由被授权的下游连接器完成。

---

## 一、能力边界

**做得到（IN）**
1. 维护单一任务账本：统一 `task_id` 命名与去重。
2. 双通道派单编排：直派通道（同步、即时）与队列通道（异步、节流）统一收口。
3. 状态机推进：待派 → 进行中 → 阻塞 / 完成 → 已验收 / 已失败。
4. 批量派单：一次指令拆多任务、统一追踪、生成汇总报告。
5. 对账：漏派、重派、超时、状态不一致检测。

**做不到（OUT）**
1. 不实际执行任务本身（不替代被派方能力）。
2. 不持有下游系统凭据——凭据只从保险库读取，永不进入对话（见第八章）。
3. 不做业务决策（验收结论由人/上游规则判定，本技能只呈现证据）。
4. 不保证下游执行成功，只保证「账本记录与对账」正确。

---

## 二、输入约束与输出承诺

**输入约束**
- 必须有明确「派单意图」：目标、执行体（或通道）、期望产出。
- 批量派单需提供任务清单（数组）或可被拆分的自然语言列表。
- 语言：默认跟随用户输入语言（核心支持 中/英/日/韩/西/法/德/阿）。

**输出承诺**
- 每次操作后返回：账本变更摘要 + 当前受影响 `task_id` 列表。
- 状态查询返回：每个任务的状态、通道、最近更新时间、阻塞原因（如有）。
- 批量收口返回：完成率、阻塞清单、需人工介入项。
- 不臆造状态；缺数据时明确标「待核验」。

## 三、触发场景

| 意图 | 触发关键词 / 句式 | 动作 |
|---|---|---|
| 单任务状态查询 | 「X 任务现在到哪了」「task-123 状态」 | 查账本，返回状态链 |
| 批量派单 | 「把这 5 件事分派出去」「批量派单给…」 | 拆单→双通道编排→收口 |
| 统一收口 | 「把今天派的全收个口」「汇总进度」 | 聚合账本，出汇总报告 |
| 对账 / 查漏 | 「有没有漏派 / 重派」「对账一下」 | 跑对账规则，列异常 |
| 阻塞排查 | 「为什么卡住了」「谁没回」 | 定位阻塞通道与执行体 |

**示例对话 1（批量派单）**
> 人：把「写周报、拉数据、发通知」三件事派出去，统一收口。
> AI：已建账本 `ledger-20260901-01`，拆为 3 个 `task_id`（直派：写周报；队列：拉数据、发通知）。完成后我会自动收口并汇报。

**示例对话 2（状态查询）**
> 人：拉数据那单现在什么状态？
> AI：`task-20260901-02` 状态=进行中，通道=队列，最近更新=10:32，无阻塞。

## 四、常见错误与反模式

**FAQ / 高频 Q&A**

Q1：批量派单后为什么没立刻全部完成？
A：双通道中队列通道是异步节流的，直派即时、队列排队。这是预期行为，非故障。

Q2：重复说「派同一个任务」会重派吗？
A：不会。账本按内容指纹去重，重复指令只更新时间戳，不新建 `task_id`。

Q3：下游执行失败了，账本怎么记？
A：状态置「已失败」，记录失败原因与重试建议，不自动掩盖。

**反模式（PROHIBITED 详见第七章）**
- ❌ 把下游凭据写进对话或日志。
- ❌ 为「看起来完成」而篡改状态。
- ❌ 跳过对账直接宣称「全部完成」。
- ❌ 用本技能执行真实写操作（它只编排）。

## 五、标准 SOP

| 步骤 | 动作 | 产出 |
|---|---|---|
| 1. 接单 | 解析派单意图，判定单/批量、通道 | 意图结构化 |
| 2. 建账 | 生成/复用 `ledger_id`，分配 `task_id`（内容指纹去重） | 账本条目 |
| 3. 拆单 | 批量时拆分为子任务，标注执行体/通道 | 任务清单 |
| 4. 编排 | 直派同步下发；队列异步入队（节流） | 派发记录 |
| 5. 追踪 | 监听状态回写，推进状态机 | 状态链 |
| 6. 对账 | 检测漏派/重派/超时/不一致 | 异常清单 |
| 7. 收口 | 聚合进度，生成汇总报告 | 收口报告 |
| 8. 归档 | 标记已验收/已失败，留存证据链 | 可审计账本 |

## 六、关键事实速查

- 命名：`ledger-{YYYYMMDD}-{seq}`；任务：`task-{YYYYMMDD}-{nn}`。
- 双通道：直派（sync）/ 队列（async, throttle）。
- 状态机：待派 → 进行中 → {阻塞, 完成} → {已验收, 已失败}。
- 去重键：任务内容指纹（标题+执行体+通道）。
- 对账四查：漏派、重派、超时、状态不一致。
- 收口报告必备：完成率、阻塞清单、需人工介入项。

## 七、铁律（PROHIBITED）

1. **严禁**把任何下游凭据、token、密钥写入对话、日志或输出文件。
2. **严禁**伪造或篡改任务状态以满足「看起来完成」。
3. **严禁**跳过对账直接宣告「全部完成」。
4. **严禁**用本技能直接执行真实外部写操作（仅编排）。
5. **严禁**替人做业务验收决策（只呈现证据）。
6. **严禁**臆造缺失数据——查不到就标「待核验」。

## 八、输入输出依赖

**输入依赖**
- 派单意图（人 / 上游 agent 提供）。
- 下游执行体可用性（直派目标、队列服务）。
- 保险库中的下游凭据（**仅运行时由授权连接器从保险库读取**）。

**输出依赖**
- 账本存储（本地文件 / 授权存储，由连接器管理）。
- 汇总报告格式（人读 Markdown / 机器读 JSON）。

**凭据红线**：所有下游凭据（API key、token、账号密码）**只从保险库读取，绝不进入对话上下文、不写日志、不回显**。本技能自身不持有凭据，仅发出「已授权」的编排指令。

## 十、错误处理

| 错误 | 原因 | 处理 |
|---|---|---|
| 派单意图缺失 | 输入无明确目标/执行体 | 退回追问，列出必填字段 |
| 通道不可用 | 直派目标离线 / 队列满 | 标记阻塞，建议切换通道或重试 |
| 下游执行失败 | 被派方报错 | 状态置「已失败」，记录原因+重试建议 |
| 对账异常 | 漏派/重派/超时 | 列异常清单，不自动掩盖 |
| 凭据读取失败 | 保险库未授权 | 中止相关派单，提示授权，不回显错误细节 |
| 数据冲突 | 同一 `task_id` 多源回写 | 以时间戳最新为准，冲突标「待核验」 |

原则：**fail visible（可见地失败）**，绝不静默成功、绝不伪造状态。
