# authz-code-design · 安全授权码与本地凭据 Broker 设计

> 发声大使：**诺卫(Phylax)** —— SynomosAI 安全 / 防线视角。

## 定位（Positioning）

本技能是一条**防线方法论**：教你怎么给 AI / 本地程序发「短时、窄域、可审计、可一键收回」的临时权限，同时让真正的密钥**永不进入模型上下文**。

**何时用**
- 需要给 AI agent 临时访问某个密钥、API、文件或设备的权限。
- 担心密钥硬编码、进上下文、被截屏 / 注入 / 长期有效。
- 需要「出事能立刻吊销」「事后能审计谁用了什么」。

**何时不用**
- 要的是云端 KMS / 实时 OAuth 第三方流转（本技能是**本地 broker** 方法论，不替代云厂商托管）。
- 需要医疗 / 临床 / 法规合规背书（本技能非医疗器械、非医疗软件、不作法规建议）。
- 你只想要一个现成库直接 import（本技能给**设计原则 + 原型骨架**，落地需按场景适配）。

## 一、能力边界

本技能覆盖以下设计维度：
1. Vault 解锁（凭据明文只活在进程内存，绝不落盘、绝进上下文）。
2. 短时 JWT 签发 / 验证（HS256，TTL 上限 900s，默认更短）。
3. scope 窄域限定（只能做被授权的事）。
4. 设备指纹（`X-Device-Id`）绑定可信终端。
5. 生物 / 解锁标记（记录标记字段，不存生物特征本身）。
6. 审计哈希链（HMAC-SHA256 append-only，防篡改）。
7. 完整吊销体系：`/revoke`（单条）、`/revoke_device`（设备）、`/revoke_title`（主体）、`/revoke_all`（一键全解绑）。
8. 只读 Dashboard（展示状态，不暴露明文凭据）。

**不生成绕过授权的代码**：本技能**拒绝**生成用于伪造令牌、绕过 scope 校验、篡改审计链、规避吊销、或反制零知识边界的任何代码或提示。授权失效 ≠ 授权可被绕过。

## 二、输入约束与输出承诺

**输入约束**
- 你描述：要保护的资源、调用方身份、期望的最小权限、可接受的时效。
- 你提供环境约束（本地 / 内网、操作系统密钥链可用性）。
- 你**不**需要提供真实密钥明文；密钥从保险库读取（见第八章）。

**输出承诺**
- 给出可落地的 broker 设计（模块职责、接口契约、字段定义）。
- 给出令牌生命周期与吊销路径。
- 给出零知识边界检查清单。
- 产出是**方法论 + 原型骨架**，不是经第三方认证的成品。

**不承诺**：生产级高可用部署、第三方合规认证、替代云 KMS。

> 用户：我让 AI 调一个内部 API，但不想把密钥写进 prompt，怎么办？
> 诺卫：用本地 broker。AI 拿到的只是一张 300 秒有效的 JWT，密钥由 broker 从 vault 解出后代理调用，明文**只活在你机器进程里**，不进对话。

> 用户：AI 跑偏了，我想立刻收回它所有权限。
> 诺卫：调 `/revoke_all` 即可全解绑；审计哈希链会记录这次吊销，事后可追溯。

## 四、常见错误与反模式（FAQ + 高频 Q&A）

**FAQ**
- **Q: 密钥别进模型上下文怎么办？**
  A: 密钥存本地 vault（密码管理器 / OS 密钥链）。AI 只持 broker 发的短时 JWT；broker 在本地进程内解密钥并代理请求。明文**绝不**出现在对话、日志、Dashboard。
- **Q: 授权能不能一键收回？**
  A: 能。提供 `/revoke_all` 一键全解绑，以及按设备 / 主体 / 单条的精细吊销；吊销事件写入审计链。
- **Q: JWT 要不要长期有效？**
  A: 不要。TTL 上限 900s，默认更短；过期即失效，降低泄露面。

**高频 Q&A**
- Q: 可以把 broker_secret 写进代码方便调试吗？ A: **不可**。每次启动随机生成，预共享需走安全信道。
- Q: 生物识别能当唯一校验吗？ A: 不能，仅作解锁标记字段，不存特征。
- Q: Dashboard 能改配置吗？ A: 只读，防凭据误暴露。

**反模式（应避免）**
- ❌ 硬编码密钥进源码 / prompt / 环境变量明文提交。
- ❌ 长时效令牌（>900s）或在上下文里传密钥。
- ❌ 跳过 scope 校验、允许令牌越权。
- ❌ 无审计、无吊销、出事无法追溯。
- ❌ 用本技能逻辑去「破解 / 绕过」别人的授权。

## 六、关键事实速查

- 签名算法：HS256（HMAC-SHA256）。
- TTL 上限：`MAX_TTL = 900s`，默认更短。
- 设备绑定头：`X-Device-Id`。
- 审计：`HMAC-SHA256` 哈希链，append-only，防篡改。
- 零知识边界：JWT、审计、Dashboard **三处均不出现明文凭据**。
- 吊销端点：`/revoke` `/revoke_device` `/revoke_title` `/revoke_all`。
- 8 维安全自测：抗暴力 / 防篡改 / 时效强制 / 抗重放 / 零知识边界 / 解绑完整性 / 并发稳定 / 边界容错。
- 网络：broker 仅监听 `127.0.0.1`，纯本地。

## 七、铁律（PROHIBITED）

1. **绝不**生成绕过授权、伪造令牌、篡改审计链、规避吊销的代码或提示。
2. **绝不**把真实密钥明文写入对话、prompt、代码、日志或 Dashboard。
3. **绝不**签发无 scope、无 TTL、可长期有效的令牌。
4. **绝不**声称已获第三方认证或合规背书。
5. **绝不**把本方法论用于攻击或破解他人授权体系。
6. **绝不**用治理框架叙事替代可落地的技术设计。

## 八、输入输出依赖（凭据从保险库读，不进对话）

- **凭据来源**：本地 vault（pykeepass / OS 密钥链 / DPAPI / Keychain）。读取在 broker 进程内完成。
- **对话边界**：对话里只出现「资源名、scope、时效、令牌 ID」，**不出现**密钥明文、解密口令。
- **口令处理**：`VAULT_PASSPHRASE` 走环境变量或交互解锁，不进上下文、不落盘日志。
- **依赖隔离**：broker 运行于独立 venv，避免与主程序依赖冲突。
- **最小暴露**：代理调用时明文密钥仅存于内存，用完即清。

## 九、示例

**示例 A：给 AI 发 300s 只读数据库权限**
```
资源: db-readonly
scope: ["db:read"]
TTL: 300s
设备: X-Device-Id = agent-laptop-01
→ broker 签发 JWT；AI 持 JWT 调 broker，broker 从 vault 解密钥代理查询。
→ 密钥明文不进对话；300s 后令牌失效。
```

**示例 B：一键收回**
```
POST /revoke_all  { "title": "agent-07" }
→ 该主体所有令牌立即失效；事件写入审计哈希链。
```

**示例 C：零知识检查清单**
```
[ ] JWT payload 无明文密钥
[ ] 审计日志无明文密钥
[ ] Dashboard 无明文密钥
[ ] 对话记录无明文密钥
```

## 十、错误处理

| 异常 | 处理 | 用户提示 |
|---|---|---|
| vault 解锁失败 | 不抛密钥，返回错误码 `VAULT_UNLOCK_FAIL` | 「凭据库解锁失败，请检查口令 / 密钥链。」 |
| JWT 校验失败 / 过期 | 拒绝请求，记录审计 | 「令牌无效或已过期，请重新申请。」 |
| scope 越权 | 拒绝，记录审计 | 「请求超出授权范围，已拒绝。」 |
| 审计链损坏 | 停止写入并告警 | 「审计链校验失败，已暂停相关操作。」 |
| 并发冲突 | `threading.Lock()` 串行化，重试上限 | 「操作冲突，已自动重试。」 |

**通用原则**：异常**绝不**泄露密钥明文；提示面向用户友好，技术细节进日志不进对话。
