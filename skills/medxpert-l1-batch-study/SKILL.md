# MedXpert·本地模型批量精读（L1）

**一句话定位**：用「DSH 任务桥 + 本地 qwen3.5:4b 模型」把一堆文档/知识库枢纽批量精读成统一格式的结构化摘要，并汇总一份「疑点总表」，全程断网、省 API 积分。

**何时用**：需要把数十/数百份医械注册、法规、文献类文档批量消化成可读摘要；希望离线、可复现、不花云端积分；产出可被人工二次核验的要点与疑点清单。

**何时不用**：文档需要联网的最新法规实时比对（本技能不联网检索）；需要生成带法律效力的注册结论（本技能只做信息整理，不做合规判定）；单份少量文档的精读（直接对话本地模型更高效，无需走任务桥）。

---

## 一、能力边界（本技能不做）

1. **不做合规判定**：只整理与提炼信息，不对文档内容做"是否符合法规/能否注册"的结论性判断。
2. **不联网检索**：不访问外网，不拉取最新法规原文，不比对外部数据库；知识时效性以你投喂的文档为准。
3. **不生成注册文件**：不产出 510(k)、NMPA 申报稿等正式文档，仅产出内部可读摘要。
4. **不处理非文本/非结构化内容**：不解析加密 PDF、扫描图片型 PDF（需先 OCR）、音视频、二进制专有格式。
5. **不保证语义 100% 正确**：模型可能误读，所有"核心要点/疑点"均需人工核验（本技能已内置「疑点」标记机制，但不替代人工）。
6. **不替代专家审阅**：疑点总表是给专家的"待确认清单"，不是结论。
7. **不做并发批调度编排**：脚本按 inbox→outbox 顺序回收，不含分布式并发与断点续跑调度（超时后需重投）。

---

## 二、输入约束与输出承诺

**输入约束**
- 文档来源：已落盘的文本型文件（.md/.txt/.pdf 文本层/.json 任务包等），先投递到 `inbox` 目录。
- 模型依赖：本地已部署 Ollama + `qwen3.5:4b`（或等价本地模型），且 `think:false` 已关闭思考链（见五、标准SOP 必做修复①）。
- 任务桥：本地 DSH 任务桥可达，`bridge timeout` 已调至 300s（见必做修复②）。
- 规模提示：单批建议 ≤ 数百份；超大批次拆批，避免超出 `max-minutes` 限时窗口。
- 文件大小：超大单文件（如 > 数十 MB）可能触发桥超时或截断，建议先切片。

**输出承诺**
- 每份文档 → 一份 Markdown 摘要，含：**核心 3 条** + **表格要点** + **疑点**三段。
- 全批完成后 → 一份 **疑点总表**（跨文档疑点汇总，便于专家逐条复核）。
- 落盘路径：由 `--outdir` 指定；命名映射由 `--names`（names.json）控制（任务 ID ↔ 文件名）。
- 失败任务：自动重投最多 3 次（`-fN` 后缀追踪第 N 次尝试），仍失败则在总表/日志中标记。

## 四、常见错误与反模式（结构化 FAQ）

**反模式 → 症状 → 正确做法**

- **错误：未关闭 qwen3 思考链（think:false）**
  → 症状：输出夹带大量 `thinking` 过程，摘要被冲淡、token 暴涨、易超时。
  → 做法：调用模型前显式设置 `think:false`，确保只回正式摘要。

- **错误：桥超时仍用默认 120s**
  → 症状：长文档精读中途断连、任务 aborted、回收为空。
  → 做法：将 DSH 桥超时由 120s 调至 300s（必做修复②），再投递。

- **错误：直接把扫描版/图片 PDF 投 inbox**
  → 症状：回收内容为空或乱码。
  → 做法：先 OCR 转文本层，或转 .md/.txt 再投递。

- **错误：inbox 与 outbox 路径写反 / names.json 缺失**
  → 症状：回收不到结果，文件名对不上原文。
  → 做法：核对 `--inbox/--outbox/--outdir/--hub/--names` 参数；准备 names.json 做 ID↔文件名映射。

- **错误：把摘要当注册结论直接用**
  → 症状：下游误用、合规风险。
  → 做法：摘要仅内部参考，疑点交专家复核，结论走正式流程。

**高频 Q&A**
- Q：断网能用吗？ A：能。依赖本地 Ollama + 本地 DSH 桥，无需外网。
- Q：失败会丢任务吗？ A：不会自动丢；脚本失败自动重投最多 3 次（`-fN` 标记），仍失败则留痕待人工重投。
- Q：支持哪些语言？ A：核心 8 种（中/英/日/韩/西/法/德/阿），默认跟随输入语言，术语标原文+译名、存疑标「待核验」。
- Q：要花 API 积分吗？ A：不花云端积分，模型在本地跑。

## 五、标准 SOP（步骤表）

| 步骤 | 动作 | 关键要点 |
|---|---|---|
| 1 | 环境就绪 | 确认 Ollama 已装、拉起 `qwen3.5:4b` |
| 2 | **必做修复①** | 模型调用设 `think:false`（关闭思考链） |
| 3 | **必做修复②** | DSH 桥超时 120s → 300s |
| 4 | 备料 | 文档转文本层，放入 `inbox/`；准备 `names.json` 映射 |
| 5 | 投递 | 按 TASK_TMPL 模板投递任务到 inbox（含输出格式规范：核心3条+表格要点+疑点） |
| 6 | 精读 | 本地 qwen3.5:4b 逐份精读（桥守护，超时受控） |
| 7 | 回收 | 脚本 `recover_l1.py` 从 outbox 回收，兼容 result/output/content 多字段、嵌套 JSON |
| 8 | 重投兜底 | 失败/aborted 任务自动重投最多 3 次（`-fN` 追踪） |
| 9 | 落盘 | 摘要写 `--outdir`（Markdown：核心3条+表格要点+疑点） |
| 10 | 汇总 | 生成跨文档**疑点总表**；`max-minutes` 到点安全退出，未完留痕 |

核心脚本：`scripts/recover_l1.py`，参数 `--inbox/--outbox/--outdir/--hub/--names/--interval(默认60s)/--max-minutes(默认45)`。

## 七、铁律（PROHIBITED）

1. **PROHIBITED** 用本技能产出"合规通过/不予注册"等结论性判定。
2. **PROHIBITED** 在 `think:false` 未关闭时投递长文档（必崩摘要质量与超时）。
3. **PROHIBITED** 桥超时仍为 120s 时跑大批量（必现 aborted）。
4. **PROHIBITED** 把扫描/加密 PDF 直接投 inbox 而不先 OCR/解密。
5. **PROHIBITED** 将摘要当作注册证据对外提交（仅内部参考 + 专家复核）。
6. **PROHIBITED** 静默忽略回收异常——JSON 解析失败须显式告警并标记任务，不得 `try/except pass` 吞掉（见十、错误处理）。
7. **PROHIBITED** 绕过 `--names` 映射导致产出与源文件失联。

## 十、错误处理

| 现象 | 根因 | 处理 |
|---|---|---|
| 回收内容为空 | 扫描/图片 PDF 未 OCR；或桥超时 aborted | 先 OCR；确认桥超时=300s；失败自动重投≤3次 |
| `thinking` 污染摘要 | think 未关 | 设 `think:false` 后重投 |
| JSON 解析异常被静默吞 | 原代码 `try/except pass` 过宽 | **改为显式告警**：捕获后打印任务 ID+字段名+原因，标记该任务待人工重投，不得静默忽略 |
| 文件名对不上源 | names.json 缺失/错配 | 补全 `--names` 映射后再跑 |
| 超时未完 | 超 `max-minutes` | 安全退出，未完成任务留痕，可分批或调大窗口后重投 |
| aborted 任务 | 桥断连/模型崩 | 自动重投（`-fN`）；超 3 次转人工 |

**错误码约定（建议）**：`E_EMPTY`（空回执）、`E_PARSE`（解析失败）、`E_TIMEOUT`（超时）、`E_ABORT`（中止）、`E_MAP`（映射缺失）。日志须带任务 ID 与码，便于定位根因。
