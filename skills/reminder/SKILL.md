## 一句话定位

reminder 是一个**轻量提醒管理技能**：帮用户创建「一次性」或「按 RRULE 重复」的提醒，并支持查询/取消已设提醒。它只管「记录与到期通知」，**不负责替用户执行任何动作**。

- **何时用**：用户说「提醒我明天 9 点开会」「每周一提醒我交周报」「我设过哪些提醒」「取消周五的提醒」。
- **何时不用**：需要真正执行任务/调用工具（交给自动化或 agent）；需要农历/节气提醒（本技能不支持）；需要跨系统短信/电话推送（依赖宿主能力，本技能只发站内/应用内通知）；需要医疗/用药提醒（非医疗器械，见免责声明）。

---

## 一、能力边界

**能做的**

- 创建一次性提醒（指定未来某时间点）
- 创建周期性提醒（使用 RRULE 标准重复规则，如每周一、每月 1 号）
- 查询当前用户所有提醒列表
- 按 ID 或条件取消/修改提醒
- 多语种识别触发（zh/en/ja/ko/es/fr/de/ar）

**不能做的（明确边界，避免误用）**

| 不支持项 | 说明 |
|---|---|
| 农历 / 传统节日 | 仅支持公历日期 + RRULE，不支持「农历初五」「除夕」 |
| 模糊时间 | 「下午」「过会儿」需用户补全为具体时间才接受 |
| 跨时区自动换算 | 默认用用户声明时区；不自动推断所在时区 |
| 真实外发推送 | 不发送短信/电话/邮件，仅站内或应用内通知 |
| 历史回填 | 只接受未来时间，过去时间直接拒绝 |
| 替用户执行动作 | 仅通知，不调用任何外部工具或 API |
| 无上限堆积 | 单会话建议 ≤ 200 条，超出提示清理 |

## 二、输入约束与输出承诺

**输入约束**

- 必填：触发时间（自然语言或 `YYYY-MM-DD HH:mm` 或 RRULE）
- 可选：提醒内容（文本）；缺省时以时间占位
- 时间必须可解析且为未来时间，否则报错并提示修正
- 重复规则须为合法 RRULE 片段（`FREQ=DAILY/WEEKLY/MONTHLY;...`）

**输出承诺**

- 创建成功：返回结构化回执（提醒 ID、下次触发时间、重复规则、内容）
- 查询：返回提醒列表（ID / 时间 / 重复 / 内容 / 状态）
- 取消/修改：返回操作结果与受影响 ID
- 失败：返回明确错误码与可操作建议（见第十章），不静默吞错

## 三、触发场景

**意图表（含优先级与共存关系）**

| 优先级 | 意图 | 触发词（中/英） | 共存说明 |
|---|---|---|---|
| P0 | 创建一次性 | 提醒我、设提醒、别忘了 / remind me | 与周期互斥，含「每周」等词归周期 |
| P0 | 创建周期 | 每周/每月/每天提醒 / every week | 含 FREQ 关键词时优先判为周期 |
| P1 | 查询 | 我设过哪些提醒、查提醒 / list reminders | 可叠加过滤条件 |
| P1 | 取消/修改 | 取消提醒、改提醒 / cancel/modify | 需 ID 或时间条件 |

- **触发优先级**：显式「每周/每月/每天/every」> 普通「提醒我」；无时间则追问，不猜测。
- **调用频率**：无硬性限流；但单次请求只处理一个主意图，复合意图拆为多次确认。

**示例对话**

> 用户：提醒我明天下午 3 点交报告
> 助手：需要具体时间，请确认是「明天 15:00」吗？（模糊「下午」需补全）
> 用户：对，15:00
> 助手：✅ 已创建 提醒ID=R-1024 触发=2026-09-02 15:00 内容=交报告

> 用户：每周一 9 点提醒我交周报
> 助手：✅ 已创建 周期提醒 R-1025 FREQ=WEEKLY;BYDAY=MO;BYHOUR=9 内容=交周报

## 四、常见错误与反模式

**结构化 FAQ（反模式 → 正确做法）**

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 重复时间冲突不处理 | 两条同触发易漏提醒 | 创建前检测同 ID/同时刻，提示合并或改名 |
| 过期提醒不清理 | 列表膨胀、查询变慢 | 过期自动标记「done」，保留 7 天后归档 |
| 时区靠猜 | 跨时区用户收到错时 | 首次要求声明时区，后续复用 |
| 用农历设节庆 | 本技能不支持 | 改用公历日期或外部农历源 |
| 堆 500+ 条不整理 | 超出建议上限 | 引导分组/定期清理 |

**高频 Q&A**

- Q：设了提醒但没收到？A：检查是否站内通知被屏蔽；本技能不发短信。
- Q：能改重复规则吗？A：能，按 ID 修改 RRULE 即可。
- Q：时区怎么算？A：以你声明的时区为准，不会自动定位。
- Q：农历生日能提醒吗？A：不支持，请用公历日期。

## 六、关键事实速查

- **RRULE 速查**：`FREQ=WEEKLY;BYDAY=MO`=每周一；`FREQ=MONTHLY;BYMONTHDAY=1`=每月 1 号；`FREQ=DAILY`=每天。
- **时间格式**：`YYYY-MM-DD HH:mm`（24 小时制）。
- **触发词**：reminder / 提醒我 / 设提醒 / 别忘了 / remind / every week。
- **上限**：单会话 ≤ 200 条；过期保留 7 天。
- **支持语言**：zh-CN, en, ja, ko, es, fr, de, ar。
- **通知方式**：仅站内/应用内，无外发。

## 七、铁律（PROHIBITED）

1. 不得发送短信、电话、邮件等真实外发推送。
2. 不得替用户执行任何外部动作或调用第三方 API。
3. 不得接受过去时间或农历/节气作为触发时间。
4. 不得猜测用户时区，必须显式声明。
5. 不得将凭据、密钥写入对话或输出（见第八章）。
6. 不得静默吞掉错误，必须返回可读错误。
7. 不得作医疗/用药提醒的有效性承诺（非医疗器械）。
8. 不得伪造提醒已送达的结果。

## 八、输入输出依赖

- **凭据来源**：如需读写提醒存储，凭据（token/密钥）仅从宿主保险库读取，**绝不出现在对话、日志或技能输出中**。
- **输入**：用户自然语言/结构化时间、提醒内容、声明时区。

- **依赖**：宿主调度能力（负责到期触发）、保险库（负责凭据）。
- **隔离**：技能逻辑与凭据解耦，密钥缺席于 SKILL 上下文。

## 十、错误处理

| 错误 | 原因 | 处理 |
|---|---|---|
| E_TIME_PAST | 时间为过去 | 拒绝并提示改为未来时间 |
| E_TIME_VAGUE | 「下午」等模糊 | 追问补全具体时刻 |
| E_NO_RRULE | 周期规则非法 | 返回合法 RRULE 示例 |
| E_LUNAR | 农历/节气 | 说明不支持，建议公历 |
| E_TZ_MISSING | 未声明时区 | 请求声明时区 |
| E_LIMIT | 超 200 条 | 提示清理/分组 |
| E_NOT_FOUND | ID 不存在 | 返回查询列表供选择 |

所有错误以「错误码 + 原因 + 可操作建议」返回，不静默失败。
