# 制度合规审查（MedXpert-COMP-001）

使用本技能在 WorkBuddy 中对中文政策、制度、规章制度草稿进行**模型自主规划式**合规审查：先按文档类型、任务材料与用户目标规划审查范围，再调用可用的法宝版 MCP 核验关键事实，执行相关审查、合并重复问题，输出结构化审查备忘录（命中原文 + 合规判断 + 问题说明 + 依据依赖 + 来源标签 + 修改建议）。主体信息需人工核验。

## 定位

**何时用**
- 审查规章制度、合同管理办法、合规制度、产品规则、隐私/数据规则、集团制度细则等**草稿**。
- 需要模型自主规划审查范围（不机械执行全部审查项），并尽量用已授权 MCP 核验法规/案例。
- 需要结构化输出：命中原文、合规判断、问题说明、依据依赖、来源标签、修改建议。

**何时不用**
- 非制度类文本（如纯营销文案、小说、个人笔记）——不在范围内。
- 需要出具法律意见书或代替法务最终结论 —— 本技能为辅助审查，结论需责任主体/法务复核。
- 需要实时联网检索但未配置法宝版 MCP —— 按第十章降级标注待核验。

## 一、能力边界（In/Out scope）

**本技能做（In）**
- 读取并整理用户选定/粘贴/上传的制度草稿（保留条文编号与原文）。
- 按 `references/review-taxonomy.md` 规划审查项，执行最小必查集 + 触发专项审查。
- 调用已授权的法宝版 MCP 核验法规/案例（未成功调用不得写"已核验"）。
- 输出 Markdown 审查报告（`.md`），可选 Word/修订说明/审批材料。
- 用来源标签（`[待核验]`/`[法宝 MCP 检索]`/`[主体信息待人工核验]` 等）标注结论可信度。

**本技能不做（Out，集中声明）**
1. 不代替法务出具正式法律意见；重大结论须责任主体/法务复核。
2. 不编造 MCP 能力或工具调用；未实际调用成功不写"已检索/已核验"。
3. 不覆盖企业工商、股权、涉诉、行政处罚等主体信息（当前法宝版不覆盖，标"主体信息待人工核验"）。
4. 不主动输出技术化 JSON 或内部字段名；用户侧一律转为自然语言/表格/风险卡片。
5. 用户未确认交付物组合前，不先生成 `.md`/Word 等交付物。
6. 不接触、不存储用户凭据；不自动发送、提交审批或覆盖原件。

## 二、输入约束与输出承诺

**推荐问法**
- `用 $regulatory-review-planner 审查这份制度草稿，并输出制度合规审查报告。`
- `审查这份《XX管理办法》，重点看权限边界和劳动者权益，输出 .md 报告。`
- `这份员工手册有没有合规风险？先审一遍，给我问题表和修改建议。`

**必填/建议字段引导**
- 制度草稿本体（上传/粘贴/选定文件；长文先用 `scripts/split_articles.mjs` 生成条文数组）。
- 审查目标与背景（发文主体、适用对象、地域、任务项目）。
- 是否需要 Word/修订版/审批材料等附加交付物（需用户确认）。

**输出承诺**
- 默认交付 `.md` 制度合规审查报告（文件名建议 `[制度名称]-合规审查报告.md`）。
- 报告含：审查备注、总体结论、关键风险、问题表（原文/问题/依据/建议/优先级）、关键条款改写文本、假设与待确认事项。
- 未生成 `.md` 文件时，不声称已完成默认交付。

## 四、常见错误与反模式

**反模式 1 ✗ 引用已废止/过时法律当现行依据**
- 错误：直接写"依据《合同法》…"而不核验时效，或多审查项重复命中却分散报告。
- ✓ 替代：引用前用已授权 MCP 核验名称与时效；引用已废止法时被 `institutional_basis`/`regulation_name_validity`/`external_organization_name`/`typo` 等可能同时命中，只报一次主问题并说明交叉命中（见 output-guidelines.md 去重规则）。

**反模式 2 ✗ 把"不适用"直接标为"不合规"**
- 错误：某条款对当前主体不适用，却判为违规。
- ✓ 替代：区分"确定问题/风险提示/不适用/需要补充背景"；"不适用≠不合规"（见 review-process.md 重要区分）。

**反模式 3 ✗ 未调取到法条却补写条款号**
- 错误：凭记忆写"依据《XX法》第X条"但未实际核验。
- ✓ 替代：无法调取时标 `[法条未调取—需核验]`；不得补写条款号（legal-source-policy.md）。

**反模式 4 ✗ 跳过最小必查集**
- 错误：只对用户点名的一项做审查，漏掉制度要素完整性等必查项。
- ✓ 替代：最小必查集（6 项）不得省略、不得用"已覆盖"替代实质判断（review-taxonomy.md）。

**反模式 5 ✗ 未确认就生成交付物**
- 错误：直接生成 `.md` 或 Word，未先确认交付物组合。
- ✓ 替代：开始前用选项确认组合（默认 `.md`，可选 Word/修订/审批材料）；用户确认前不生成。

**反模式 6 ✗ 把模型记忆当已核验依据**
- 错误：用训练知识直接下确定性结论而不检索。
- ✓ 替代：涉及现行法规时效、处罚权限、个人信息、公平竞争、劳动者权益、监管要求、司法趋势时，未检索不得作确定性表述；来源冲突时披露并转人工法务复核。

**高频 Q&A**
- Q：能审哪些制度？A：规章制度、合同管理办法、合规制度、产品规则、隐私/数据规则、集团细则等草稿；非制度文本不在范围。
- Q：法规怎么保证现行有效？A：优先用已授权法宝版 MCP 核验；无法核验标 `[待核验]`/`[法条未调取—需核验]`，不凭记忆。
- Q：企业工商/涉诉信息能查吗？A：当前法宝版不覆盖，统一标 `[主体信息待人工核验]`，由你方核实。
- Q：一定要生成 Word 吗？A：默认只出 `.md`；Word/修订/审批材料为可选，需你确认后生成。
- Q：长制度怎么处理？A：先用 `scripts/split_articles.mjs` 拆条文，再做条文目录与详细审查。

## 五、标准 SOP

**不许跳步**。核心流程：

| 步 | 动作 | 产物 | 易踩坑 |
|----|------|------|--------|
| 1 读取与整理 | 用平台文档读取能力读草稿；长文先 `scripts/split_articles.mjs` 拆条文；识别文档类型/主体/范围/目标 | 条文数组 `draft_articles`、文档画像 | 忽略条文编号；粘贴文本未拆条导致漏审 |
| 2 规划审查范围 | 读 review-taxonomy.md 选审查项；读 tool-integration-policy.md、legal-source-policy.md 定可用MCP与降级；先执行最小必查集6项，再按触发线索加专项 | 审查计划（必查+专项） | 跳最小必查集；未读策略文件误用工具 |
| 3 工具核验与分层执行 | 按 MCP 策略调用；未成功不得写"已核验"；按六层推进（要素/结构/权责/法律风险/语义/语言）；高风险问题依据含"法规名+条款号+核心规则+来源状态" | 分层审查结果（带来源标签） | 未调取却补条款号；把"不适用"标"不合规" |
| 4 归并与排序 | 合并同实质问题，保留最强依据；按严重程度与整改影响排序 | 去重后问题清单 | 重复问题分散；技术化 JSON 直出 |
| 5 交付 | 先确认交付物组合（默认 `.md`）；生成报告含备注/结论/关键风险/问题表/建议条款/假设待确认 | `.md` 报告（可选 Word 等） | 未确认先生成；未生成 `.md` 却声称完成 |

**最小必查集（不得省略）**：①制度要素完整性（标题/目的/适用范围/主管部门/职责/生效废止/解释权/附件/流程闭环）②制定依据与效力（引用法规是否现行有效、名称准确、层级匹配）③权限边界（是否越权设审批/处罚/检查/处分/扣款/数据处理/强制义务）④结构与内部一致性（章节/编号/定义/前后引用/附件/流程冲突）⑤执行可操作性（责任主体/审批路径/时限/证据留存/例外/申诉监督）⑥语言文字规范（禁止/强制表述准确、无歧义错字）。

**触发专项审查**：个人信息/数据→个人信息保护；采购/招投标→公平竞争非歧视；员工/劳务派遣/处分/工资/假期→劳动者权益（读 employment-review-precision.md）；法律法规/政策/内部制度名称→名称准确性与时效性；集团/上级制度/模板→上级制度冲突。

## 六、关键事实速查

- **可用 MCP（仅已授权且实际返回可用）**：`mcp-law-search.search_article`（优先检索入口）、`law-pkulaw-mcp.get_law_list`、`mcp-law-search.get_article`、`fatiao-pkulaw-mcp.get_law_item_content`、`chat-web.adjust_provisions`/`law-recognition.law_recognition`（核验条款）、`case-pkulaw-mcp.get_case_list`/`pkulaw-mcp-case-search.search_case`（类案）、`case-number-recognition.anhao_recognition`/`add-doc-link.get_linked_content`（案号/跳转来源）。具体可用性以当前任务授权为准（**待核验**）。
- **来源标签**：`[用户提供材料]`/`[审查规则]`/`[法宝 MCP 检索]`/`[官方来源]`/`[主体信息待人工核验]`/`[模型知识—需核验]`/`[法条未调取—需核验]`/`[案例未调取—需核验]`/`[上级制度未取得—需核验]`/`[内部材料待补充]`。
- **主体信息**（工商/股权/涉诉/处罚）当前法宝版不覆盖，统一标 `[主体信息待人工核验]`。
- **官方来源链接与法规条文可达性一律待核验**，以实际返回与官方公布为准；不得用模型记忆冒充已核验依据。
- 审查项体系详见 `references/review-taxonomy.md`（六类：要素完整性/结构与格式/权责与权限/法律与合规风险/语义一致性/语言文字规范）。

## 七、铁律（PROHIBITED 绝对禁止）

1. **绝不写"已核验/已检索"于未实际调用成功的 MCP** —— 只将实际返回内容作为依据。
2. **绝不编造法规条款号或案例** —— 未调取原文标 `[法条未调取—需核验]`，不得补写。
3. **绝不把模型记忆当已核验法律依据** —— 涉时效/处罚/个人信息/公平竞争/劳动/监管/司法趋势，未检索不下确定性结论。
4. **绝不省略最小必查集** —— 6 项必查不得用"已覆盖"替代实质判断。
5. **绝不未确认交付物组合就生成 `.md`/Word** —— 须先确认（默认 `.md`，可选附加）。
6. **绝不输出技术化 JSON 或内部字段名给用户侧** —— 一律转自然语言/表格/风险卡片。
7. **绝不自动发送、提交审批或覆盖用户原件** —— 生成新文档或副本，由用户处置。

- **环境/凭据**：本技能**不读取任何凭据**。如接入 MCP 需要令牌，从保险库 `~/.ucvault_local` 读取，**绝不**进入对话、代码或日志；当前由平台/用户侧授权管理，技能仅按授权调用。

## 九、示例

**示例 1：通用制度审查（端到端）**
- 问题：审查《供应商管理办法》草稿，看越权设处罚与上级制度冲突。
- 加载：Step1 读取 → Step2 规划（最小必查集 + 权限边界 + 上级制度冲突专项）→ Step3 MCP 核验 → Step4 归并 → Step5 确认组合后交付。
- 答案框架：审查备注（已读材料/未核验项）｜总体结论（可推进/修改后推进/需重写）｜关键风险 3–7 项｜问题表（原文/问题/依据[法规名+条+摘要+来源状态]/建议/优先级）｜建议条款（可复制完整文本）｜假设与待确认。

**示例 2：员工制度专项**
- 问题：这份员工手册的加班、竞业限制、个人信息检查条款有没有风险？
- 加载：规划时触发劳动者权益专项 → 读取 `references/employment-review-precision.md` → 按专项子项（工时/加班/年休假、竞业限制、IP、个人信息与检查权、处分解除）展开。
- 答案框架：分专项问题表（如工作日延时/休息日/法定节假日加班分别处理）｜建议条款（带占位条件并标待确认）｜`[主体信息待人工核验]` 标注。

**示例 3：长制度拆条后审查**
- 问题：一份 80 条集团制度细则，怎么高效审？
- 加载：先 `node scripts/split_articles.mjs 制度.txt draft_articles.json` 拆条 → 制作条文目录 → 按六层审查。
- 答案框架：条文目录 + 分层问题表 + 跨条冲突/编号重复提示 + 去重后报告。

## 十、错误处理

本技能为流程型，无系统错误码；以下为异常场景降级与修正引导（约 6 类）。

| 错误码 | 现象 | 原因 | 修正引导 |
|--------|------|------|----------|
| E-IN-001 | 无法读取用户文档/无输入 | 文件不可读或仅口头描述 | 优先用平台文档读取；不可用时请用户粘贴文本或给本地可访问文件路径，并在审查备注说明 |
| E-MCP-002 | 法宝版 MCP 不可用/无结果 | 未授权或工具异常 | 标 `[待核验]`/`[法条未调取—需核验]`/`[案例未调取—需核验]`；不得用模型记忆补足 |
| E-SUB-003 | 结论依赖主体工商/涉诉状态 | 法宝版未覆盖主体信息 | 统一标 `[主体信息待人工核验]`，由用户方核实后定稿 |
| E-SCOPE-004 | 收到非制度类文本（如小说/营销稿） | 偏离声明场景 | 回退至制度合规审查范围；非制度内容告知不在职责内 |
