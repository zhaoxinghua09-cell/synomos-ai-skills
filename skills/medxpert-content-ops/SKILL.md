## 一句话定位

本技能是 MedXpert 对外内容生产与官网运维的**单一事实源（SSOT）规范包**：把视觉规范、AI 友好隐藏原则、内容原则、乐享→官网同步流程、整站改版纪律与页面检查清单固化成一册，让 AI 与运营在「不踩红线、不乱套旧版、全站口径一致」的前提下产出合规内容。

- **何时用**：要写/改官网页面、公众号文案、对外物料；要做乐享→官网同步；要核对 VI 配色、AI 友好红线、内容脱敏与法规引用；要排查「配色选错」「同步失败」「AI 友好字样残留」等问题。
- **何时不用**：纯内部研发文档、与 MedXpert 品牌无关的通用写作、需要直接改线上域名/托管/收录（由 Steven 操作，本技能只备内容与指引）、需要医学诊断或注册法规出具正式意见（本技能只给口径与流程，不替代专业合规结论）。

## 四、常见错误与反模式（结构化 FAQ + 高频 Q&A）

> 每条先给「反模式（✗）」，再给「替代方案（✓）」，避免只列禁止项。

**FAQ-1：在官网/公众号直接写「本页面 AI 友好、AI 可读」**
- ✗ 反模式：人类可见面出现「AI 友好 / 让 AI 读得懂 / AI 可调用 / AI 索引」等表述。
- ✓ 替代：人类文案走「专业 / 知识库 / 权威 / 可追溯」话术；AI 可调用能力只在机器通道体现（llms.txt、llms-full.txt、robots.txt 放行 10 个 AI 爬虫、sitemap、RAG 检索）。
- 依据：AI 友好隐藏原则（二）。

**FAQ-2：改版只改首页，子页长期停在旧红系**
- ✗ 反模式：8-18 VI v2 定稿后只改首页，knowledge/子页停留在旧红系，造成整站断层。
- ✓ 替代：改版前先列全站页面清单并登记版本状态；一次性批量或分批排期升级，**不留「等有空再改」的遗留页**；手写页与脚本渲染页都要覆盖。遗留页登记在「VI 覆盖状态」随时可查。
- 依据：整站改版纪律（一·补）。

**FAQ-3：同步失败就反复硬跑脚本**
- ✗ 反模式：渲染报错后不查源直接重试，或跳过验证步骤。
- ✓ 替代：按第十章错误码定位（MCO-201 源缺失 / MCO-202 渲染异常 / MCO-203 残留检出），先修源再跑；跑完必过 grep 验证 AI 友好字样为 0。
- 依据：SOP 验证步（五）+ 错误处理（十）。

**FAQ-4：把第三方资料原样搬运并标注出处**
- ✗ 反模式：直接复制客户/第三方内容并注明「来源：XXX」。
- ✓ 替代：改写成原创表述，不原样搬运、不标第三方出处；客户信息脱敏；法规引用带文号并核现行有效。
- 依据：内容原则（二/三）。

**FAQ-5：过度防复制（禁右键/禁选中/禁 Ctrl+A）**
- ✗ 反模式：为保护内容禁用右键、选中、全选。
- ✓ 替代：仅保留复制来源水印，**不禁右键/禁选中/禁 Ctrl+A**（过度防护伤害真实用户，2026-08-20 已移除）。

**高频 Q&A**
- Q：配色选错了怎么救？A：立即回退到 VI v2 浅蓝家族（见六），旧红系/深蓝为废弃版，不得用于新产出。
- Q：同步后 FAQ 条数对不上？A：以乐享源为准，验证步要求 FAQ 30 条、案例 3 个；不足则回源补，再渲染。

- Q：法规文号过期了怎么办？A：以《法规文号事实库》《标准作废状态核实清单》核对（待核验），冲突处标注「以现行版为准」。

## 十、错误处理

> 文档型 Skill 无运行崩溃风险，但操作易踩红线/漏步。以下用「错误码 + 现象 + 原因 + 修正」给出修正引导，而非只说「不许」。

| 错误码 | 现象 | 可能原因 | 修正引导 |
| --- | --- | --- | --- |
| MCO-101 | grep 检出「AI 友好/AI 索引」字样 | 人类文案用了技术黑话 | 替换为「专业/知识库/权威/可追溯」；重跑 grep 至 0 残留 |
| MCO-102 | 页面出现旧红系/深蓝配色 | 在旧版上叠新内容或未套 v2 | 回退 VI v2 浅蓝家族；遗留页登记 VI 覆盖状态排期升级 |
| MCO-201 | `sync_lexiang_website.py` 源缺失报错 | 未先拉取乐享源 / 目录错 | 先 `block_fetch_page` 到 `website/_lexiang_sync/`；核对目录路径（待核验） |
| MCO-202 | 渲染异常 / 样式错乱 | 脚本未含 v2 或手写页样式未同步 | 确认脚本为内置 v2 版；手写页（index/services/about/legal）同步样式 |
| MCO-203 | 验证 FAIL：FAQ≠30 或案例≠3 | 乐享源缺条目 | 回乐享补 FAQ/案例至达标，再渲染验证 |
| MCO-204 | 客户信息泄露风险 | 第三方资料未脱敏即写入 | 截断证号后段、隐去公司名/人名；改写原创化 |
| MCO-205 | 对外口径不一致 | 只改官网未同步乐享/公众号 | 以乐享为唯一源，改一处即同步其余处 |
| MCO-301 | AI 扫描引导未生效 | 口令未放高亮位 / 用了黑话 | 放 knowledge hero 下方高亮区 + 首页提示条；用自然话术「给我去装 MedXpert」 |

**通用修正原则**：先对照第七章铁律确认是否踩禁区 → 再回第五章 SOP 补漏步 → 最后重跑验证（grep + 条数 + 配色）至全绿再发布。
