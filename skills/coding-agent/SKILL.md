# coding-agent · 后台编码委托技能

**定位**：一套「把编码任务交给后台 AI 编码代理（Codex / Claude Code / OpenCode）跑」的方法论与编排指南。它不替代你写代码，而是把**长耗时、可并行、低风险**的编码工作委派给后台进程，并把派单→执行→回收的全过程留痕（证据链），便于审计与回溯。

**何时用**：
- 大型重构 / 跨文件改名 / 批量接口改造等耗时任务
- PR 自动审查、自动修复 lint/test 失败
- 后台功能开发、样板代码生成、文档/注释补全
- 你需要在等待期间继续做别的事（人机并行）

**何时不用（边界）**：
- 需求不清、目标频繁变动的小任务（直接手写更快）
- 实时交互、毫秒级反馈场景（后台异步不适合）
- 涉及生产密钥、未授权仓库、强合规红线的高危改动（须人工 + 人类监督）
- 单文件 < 50 行且 5 分钟内能改完的琐事

## 一、能力边界

| 维度 | 说明 |
| --- | --- |
| 能做 | 派单给后台编码代理、轮询进度、回收 diff/结果、汇总证据链（谁、何时、改了什么） |
| 输入规模上限 | 单次委托建议 ≤ 50 个文件、≤ 5000 行改动；超出请拆分多单 |
| 复杂度上限 | 仅限「目标明确、可验证」的任务；禁止开放式的「随便优化一下」 |
| 输出约束 | 必须返回可审查的 diff + 执行摘要；禁止直接静默 push 到受保护分支 |
| 不适用 | 实时任务、需求模糊、强合规红线、生产密钥相关改动（见上「何时不用」） |
| 不保证 | 不保证编译/测试一次通过；不保证代理选型最优；不替代人类 code review |

## 二、输入约束与输出承诺

**输入约束**
- 必须提供：任务目标（一句话）+ 范围（文件/目录/分支）+ 验收标准（如何算完成）
- 可选提供：约束（不可改的文件、风格规范）、上下文（相关文档链接）
- 禁止提供：明文密钥、token、密码（见第八章，须从保险库读取）
- 语言：默认跟随用户输入语言；可要求中英对照

**输出承诺**
- 结构化结果：`状态 / 改动文件清单 / diff 摘要 / 证据链 ID / 下一步建议`
- 失败也必须返回：明确错误码 + 已完成的局部进度（不丢成果）
- 所有产出默认只读呈现，写库/推送需显式授权

## 三、触发场景（意图表 + 示例对话）

| 用户意图 | 触发示例 | 应做的动作 |
| --- | --- | --- |
| 大重构丢后台 | 「这个重命名涉及 30 个文件，能丢后台跑吗」 | 拆解任务→委派→轮询→回收 |
| 自动审 PR | 「帮我把这个 PR 的 lint 问题和测试失败修掉」 | 拉取 PR→修复→出 diff→等人工合 |
| 后台功能开发 | 「用 OpenCode 在后台把导出模块写出来」 | 选 agent→派单→回收结果 |
| 批量样板 | 「给所有 model 补上注释」 | 范围扫描→批量生成→差异汇总 |

**示例对话**
> 用户：把 `src/api/*` 的鉴权逻辑统一成中间件，能后台跑吗？
> 技能：可以。这是低风险、可验证重构，符合边界。我会委派给后台代理，范围 `src/api/*`，验收=「所有接口走中间件且测试通过」。是否开始？（我会先给计划，不静默改动）

**与编码代理的集成**
- Codex / Claude Code：通过各自 CLI 以后台子进程启动，捕获 stdout 作为证据
- OpenCode：本地优先，适合国内网络受限场景（见第六章 domestic 说明）
- 统一抽象：本技能只定义「派单协议」，具体 agent 由用户环境决定

## 四、常见错误与反模式（FAQ + 高频 Q&A）

**反模式（请勿这样做）**
- ❌ 把「需求不清」的任务整包丢后台 → 代理会自由发挥，结果不可控
- ❌ 在 prompt 里贴 API key / 密码 → 泄露且进对话日志
- ❌ 让后台代理直接 push 到 main / 受保护分支 → 失去人类监督
- ❌ 单委托塞 200 个文件 → 超时、diff 爆炸、难 review
- ❌ 拿到 diff 不审就 merge → 违背 AI 世界共生论的人类监督原则

**高频 Q&A**
- Q：后台跑了但没结果？A：先查状态轮询，超时使用 E-003 重试策略（见第十章）。
- Q：代理选型选哪个？A：国内优先 OpenCode（本地）；海外可用 Codex/Claude Code。
- Q：能并行多单吗？A：能，每单独立证据链 ID，互不污染。
- Q：改错了能回滚吗？A：默认只出 diff 不写库；写库前必须显式授权，可用 git 回退。

## 六、关键事实速查

- 核心三代理：Codex、Claude Code、OpenCode（可插拔）
- 证据链四要素：任务 ID / 代理身份 / 时间 / diff 哈希
- 默认策略：只读呈现，写库需授权
- 国内网络：Codex、Claude Code 受地理访问限制 → 优先 OpenCode 本地部署
- 单委托上限：≤50 文件 / ≤5000 行
- 许可证：MIT；版权：SynomosAI

## 七、铁律（PROHIBITED）

1. 禁止在对话/ prompt 中携带明文密钥、token、密码
2. 禁止后台代理静默 push 到受保护分支（main/master 等）
3. 禁止派发需求模糊、无验收标准的开放式任务
4. 禁止跳过人类监督直接合入合规/生产相关改动
5. 禁止单委托超过规模上限（50 文件 / 5000 行）而不拆分
6. 禁止伪造或篡改证据链（谁/何时/改了啥必须真实）
7. 禁止把本技能用于未授权仓库或越权操作

---

## 八、输入输出依赖（凭据从保险库读，不进对话）

- **依赖项**：目标仓库访问权、后台 agent 可执行文件（Codex/Claude Code/OpenCode）、可选 lint/test 环境
- **凭据来源**：所有密钥/ token 必须从本地保险库（如 `unified-credential-vault` / DPAPI 本地保险库）读取，**绝不**出现在 SKILL.md、对话或 prompt 中
- **读取方式**：由宿主环境在运行时注入到 agent 进程环境变量；本技能只消费「已就绪的凭据句柄」，不接触明文
- **失败兜底**：保险库不可用时，任务中止并报 E-001，不降级为明文传参
- **数据流向**：用户输入 → 本技能（编排） → 后台 agent（执行） → 结构化结果回流；密钥不参与回流

## 十、错误处理

| 错误码 | 场景 | 处理策略 | 用户可见提示 |
| --- | --- | --- | --- |
| E-000 | 越界/需求不清 | 驳回并给改进建议 | 「不在能力边界，建议细化后重试」 |
| E-001 | 保险库/凭据缺失 | 中止，不降级明文 | 「凭据不可用，任务已停止」 |
| E-002 | agent 未安装/不可达 | 切换可用 agent 或报错 | 「所选代理不可用，请安装或换 OpenCode」 |
| E-003 | 任务超时/中断 | 保存局部进度，指数退避重试（≤3 次） | 「任务超时，已保留进度，重试中」 |
| E-004 | 测试/lint 失败 | 返回失败 diff + 日志，不自动强合 | 「校验未过，见差异与日志」 |
| E-005 | 越权写受保护分支 | 阻断并告警 | 「已拦截对受保护分支的写入」 |

**降级原则**：任何异常都优先「保成果、保人类监督、保证据真实」，绝不静默成功、绝不绕过铁律。

- **输出规则**：默认跟随输入语言；用户可要求多语种输出（如中英对照）
- **触发**：用户用上述任一语言提问即可，无需切换指令
- **质量**：术语/法规/专业内容多语种时，标注原文与译名，存疑标「待核验」
- **扩展**：支持扩展更多小语种（意/葡/俄/泰/印尼/越等）
