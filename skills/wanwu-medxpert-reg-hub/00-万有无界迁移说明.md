# 万有无界技能迁移 · 试点说明（medxpert-reg-hub）

> 本目录是「咱们的技能能否放到万有无界」可行性验证的**第一个落地试点**：把 WorkBuddy 的 `medical-device-reg-hub`（医械注册枢纽）转成万有无界就绪技能包。

## 一、核心结论（推翻了之前的悲观判断）
查万有无界官方文档（docs.wanyo.cn）后确认：**万有无界的自定义技能 = 上传一个 zip 包，里面必须含 `SKILL.md`**，描述从 `SKILL.md` 的 `description` 字段读取。
→ 它和 WorkBuddy / Claude 是**同一套 SKILL.md 范式**，不是"格式全重写"。
→ 迁移 = 同范式 + 补 `README.md` + 打包 zip + 过三项认证。**纯知识型技能几乎零改造**。

## 二、万有无界技能装配规则（来自官方文档）
- 上传 zip，必须含 `SKILL.md`（根目录或子目录均可），可选 `scripts/`、`examples/`、`resources/` 等，≤10MB。
- 表单自动预填：标识←`name`、显示名称←`displayName`、描述←`description`（≤200 字，可改）、版本默认 `1.0.0`。
- 三项认证：
  - 安全认证（10 项：漏洞利用/数据窃取/恶意软件/网络攻击/身份伪造/危险操作识别等）
  - 完整性认证（5 项：README.md 已声明、SKILL.md 已声明、依赖项已声明、运行环境已说明、数据配置已声明）
  - 可执行性认证（隔离沙箱跑通 SKILL.md 能力，5 用例任一通过即可）
- Agent 自定义创建时选运行引擎：Claude Code 或 OpenClaw；可智能匹配/手动装技能（单次≤10 个）。
- 本地 Agent 也可通过 curl 临时命令接入（A2A 思路，适合强工具依赖型技能）。

## 三、本试点做的适配（仅 2 处）
| 适配点 | 原状态 | 万有无界要求 | 处理 |
|---|---|---|---|
| `description` 长度 | 329 字 | ≤200 字 | 精简为 78 字（见 SKILL.md 第 8 行） |
| 技能级 `README.md` | 缺（仅插件根有） | 完整性认证强制 | 新建，声明用途/依赖/运行环境/数据配置 |

其余（frontmatter 的 name/slug/displayName/version/license、references/ 知识枢纽、assets/ 全景图）**原样保留**，万有无界可直接识别。

## 四、上线步骤（需你自己的万有无界账号操作）
1. 把本目录 `wanwu-pilot-medxpert-reg-hub` 打包为 zip（341K，符合 ≤10MB）。
2. 登录万有无界（qianwenai.com/agents/wanyou，公测邀请码 `19PMH5QW`），进「技能市场 → 发布新技能」。
3. 上传 zip，确认预填信息，补一段变更说明，提交审核。
4. 审核通过后，新建自定义 Agent（运行引擎 Claude Code / OpenClaw，工作职责填"医械注册工程师"），智能匹配或手动装入本技能即可使用。

## 五、对 13 个插件迁移的启示
- 🟢 纯知识型（medxpert-reg-hub、medxpert-llm-library、opc-company-formation）：同此法，仅调 description + 补 README，**半天级**可上线。
- 🟡 团队/SOP 型（market-research-team、medxpert-registration-ops、medxpert-traceability-audit 等）：Skill 同法迁移；其内嵌的「多 Agent 角色」拆成万有无界「项目空间 + 群聊」里的多个自定义 Agent 组队，模型天然同构。
- 🔴 强工具依赖型（content-publish-ops 发布动作、medxpert-ops-team 的 COS/Ardot、content-growth-ops 微信 OA）：SOP 同法迁移，但"动作"需走 A2A 本地接入保留 WorkBuddy 运行时，或替换为万有无界等效工具/MCP。
- ⚫ wb-safe-team：守护 WorkBuddy 本体，价值仅限 WB 用户，不建议迁移。
