# 设计开发控制枢纽

需求立项之后，设计开发阶段的质量决定注册成败——设计输入/输出、评审、**验证与确认**、设计转移、设计变更，全部是 ISO 13485 7.3 / 21 CFR 820.30 的强制要求，也是体系核查与注册审评的重点。本枢纽汇总设计控制全流程要点与官方入口，全部链接复用枢纽系列已核验清单。

> 制作日期：2026-08-18 ｜ 链接核验：全部复用枢纽系列已核验链接（eCFR 820、ISO 13485、FDA 过程验证、认可标准库），零新增核验

---

## 一、设计控制法规框架

| 市场 | 依据 | 说明 |
| --- | --- | --- |
| 国际/中国 | **ISO 13485 7.3**（中国 YY/T 0287 等同） | 设计开发策划/输入/输出/评审/验证/确认/转移/变更全流程 |
| 美国 | **21 CFR 820.30**（Design Controls） | FDA 设计控制强制要求，QMSR 过渡后并入 ISO 13485 体系 |
| 欧盟 | MDR Annex I GSPR + Annex II 技术文档 | 设计与制造信息须在技术文档中可追溯 |

> 关键提示：设计控制的本质是**可追溯**——每条需求（设计输入）→ 每个规格（设计输出）→ 每项测试（验证/确认）必须能对得上，这就是注册审评和体系核查"追着问"的东西。

---

## 二、设计控制九步流程

```
设计输入 → 设计输出 → 设计评审（阶段门）→ 设计验证 → 设计确认
    → 设计转移 → 设计变更 →（全程 DHF 文档化）
```

| 步骤 | 要点 |
| --- | --- |
| ① 设计输入 | 用户需求 + 法规标准 + 风险输出 + 可用性/灭菌/包装要求；**每条输入可验证**（呼应「需求调研与立项枢纽」） |
| ② 设计输出 | 图纸、规格书、BOM、产品技术要求、检验方法——**对照输入逐条追溯** |
| ③ 设计评审 | 阶段门评审（概念/样机/试产），跨职能（研发+RA+质量+生产） |
| ④ 设计验证（Verification） | **"做对了没有"**：输出满足输入——性能测试、生物相容（ISO 10993）、灭菌确认（ISO 11135/11137）、软件测试（IEC 62304） |
| ⑤ 设计确认（Validation） | **"做对了产品没有"**：满足预期用途/用户需求——可用性评估（IEC 62366）、临床评价（呼应「临床评价枢纽」） |
| ⑥ 设计转移 | 设计输出转化为**生产规范**（DFM、工艺参数、IQ/OQ/PQ 过程确认、试产）（呼应「GMP 质量体系与验证枢纽」） |
| ⑦ 设计变更 | 变更评估与再验证/再确认（呼应「变更延续管理枢纽」） |
| ⑧ DHF 文档化 | 设计历史文件：全流程记录可追溯（欧盟对应技术文档） |

> 验证 vs 确认一句话区分：**Verification = 做对了没有（对不对规格）；Validation = 做对了产品没有（满不满足用户）**。两者都要做，顺序不能反。

## 三、各环节的联动枢纽

| 设计环节 | 联动枢纽 |
| --- | --- |
| 设计输入（风险/可用性） | 「风险管理枢纽」ISO 14971、「软件人因枢纽」IEC 62366 |
| 设计验证（测试） | 「生物相容性测试规划枢纽」ISO 10993、「灭菌包装验证枢纽」ISO 11135/11137/11607 |
| 设计验证（软件） | 「软件人因枢纽」IEC 62304、FDA 三级关注 |
| 设计确认（临床） | 「临床评价枢纽」同品种/临床试验 |
| 设计转移（工艺） | 「GMP 质量体系与验证枢纽」IQ/OQ/PQ、FDA Process Validation |
| 设计变更 | 「变更延续管理枢纽」变更控制 |

## 五、常见误区

- ❌ 验证和确认混为一谈 → Verification 对规格、Validation 对用户，**两个都做、顺序不反**
- ❌ 设计输出和输入对不上 → 审评第一刀就砍"需求-规格-测试不闭环"
- ❌ 设计转移靠"口头交接" → 必须转化为受控生产规范 + 过程确认（IQ/OQ/PQ）
- ❌ 变更只改图纸不评估 → 每次变更评估是否需再验证/再确认/重新申报（呼应「变更延续管理枢纽」）
- ❌ DHF 事后补 → 设计控制的价值在"过程留痕"，审评和飞检看的就是记录完整性
