# Summarize Pro（增强总结 · SynomosAI 内容治理防线）

一句话定位：**把长篇/杂乱的输入，按用户指定的格式与受众，压成忠实于原文、可追溯、标注不确定项的总结。**

- **何时用**：长文摘要、会议纪要、方案对比、时间线梳理、行动清单提取、跨文档要点聚合、多语种内容归纳。
- **何时不用**：需要原创创作/改写/翻译润色（非总结）、需要实时音视频转写、需要给出原文未载的事实或数据、需要规避版权或内容审核、需要冒充人类原创产出。

> 治理与溯源：本技能为 SynomosAI 品牌标准能力，版权 SynomosAI · MIT。所有总结须保留来源可追溯性，遵循 XCGS 治理与 A³ 法则安全护栏。

## 一、能力边界（本技能不做）

集中声明「本技能不做」以下事项，避免被误用或越界：

1. **不编造**：原文没有的事实、数据、结论、引文，一律不补写；确有需要时只标「存疑/待核验」。
2. **不翻译改写原文**：默认不翻译（除非用户明确要求多语种输出）、不润色成原创文风、不改写事实表述。
3. **不去除来源与版权**：不得在输出中抹除作者、出处、版权标识或水印信息。
4. **不规避审核**：不得为绕过内容审核、合规检查而「美化」「洗稿」敏感原文。
5. **不处理实时音视频**：不接受未转写的音视频流；仅处理已有文稿/字幕/文本。
6. **不提供法律/医疗/金融等专业结论的确定性判断**：可归纳原文观点，但不得替代专业意见或出具确定性结论。
7. **不做未经授权的敏感内容总结**：涉密、明显违禁、未获授权披露的个人隐私类内容，拒绝处理。
8. **不超量承诺**：单轮建议输入 ≤ 50,000 字（约 200 页）；超出须分块或仅做高层摘要（见第二章）。

## 二、输入约束与输出承诺

### 输入约束（推荐问法）
- **格式**：纯文本、Markdown、网页（WebFetch 抓取）、本地文件（Read 读取）。
- **体量**：单次 ≤ 50,000 字；超出请分块提交，或明确「只做一句话摘要/三段摘要」。
- **必填信息**：①待总结内容或来源；②期望输出格式（如会议纪要）；③受众/用途（领导/执行/同行/公众）。缺③时默认「通用读者+标准总结」。
- **推荐问法模板**：
  `把[来源]按[格式]总结给[受众]，重点突出[主题]，长度约[字数]。`
  例：`把这篇报告按会议纪要总结给执行层，重点突出风险与待办，约 400 字。`

### 输出承诺
1. **格式规范**：严格套用第五章对应模板；未指定格式时默认「标准总结」。
2. **忠实可溯**：每条关键结论能回指原文锚点（章节/段落/行号/时间戳）。
3. **标注不确定项**：原文缺失、歧义、冲突处显式标注「存疑/待核验/有冲突」。
4. **不越界**：不输出原文未载的事实；不替代专业判断。
5. **语言**：默认跟随输入语言；用户可要求中英对照等多语种输出。

## 四、常见错误与反模式

### 结构化反模式（错误模式 → 典型症状 → 正确做法）
| 错误模式 | 典型症状 | 正确做法 |
|----------|---------|----------|
| 凭记忆补写 | 输出出现原文没有的数据/人名/结论 | 严格真实参照法，缺则标「存疑」，不补 |
| 格式错配 | 要「给领导看」却堆满技术细节 | 按受众切换粒度（见第五章粒度表） |
| 去溯源 | 摘要无任何来源锚点，无法核证 | 每条关键结论挂回原文位置 |
| 洗稿脱敏 | 为「好看」改写事实、抹版权 | 保持原意与来源，仅压缩不篡改 |
| 超量硬塞 | 一次喂 10 万字导致丢段/幻觉 | 分块总结或先做高层摘要，再逐块 |
| 冒充原创 | 不注明「AI 总结」、去水印 | 输出头部标注「AI 生成总结 · 来源：…」 |

### 高频 Q&A
- **Q：输出格式不符合预期怎么办？** A：在请求里显式指定格式关键词（见第三章表），并给受众与长度。
- **Q：原文冲突/自相矛盾？** A：不强行调和，并列双方并标「有冲突」，交用户判断。
- **Q：能总结英文/日文资料吗？** A：能，8 种核心语言均支持，默认同语言输出，可要求中英对照。
- **Q：可以帮我改写得更通顺吗？** A：本技能只总结不润色；如需改写请另用创作类技能，并保留来源。
- **Q：内容很长怎么办？** A：分块提交，或先要「一句话/三段摘要」，再逐块深究。

## 五、标准 SOP

### 核心方法论：真实参照法（Real-Referencing）
1. **提取**：通读原文，抽取事实/主张/数据/结论，每条记来源锚点（章节·段落·行号·时间戳）。
2. **压缩**：合并同类、删冗余、降噪，不改变原意。
3. **悬挂**：每条关键结论必须能回指原文；无法回指的，删或标「存疑」。
4. **标注**：原文没有的信息绝不补；歧义/冲突显式标注。
5. **定稿**：按受众/用途切换粒度，套用对应输出模板。

### SOP 步骤表
| 步骤 | 调哪个文件/工具 | 交付物 | 最易踩的坑 |
|------|----------------|--------|------------|
| 1. 收输入 | Read / WebFetch / 用户粘贴 | 原文文本+格式+受众 | 漏问受众→默认通用，领导看不懂 |
| 2. 定格式 | 第三章意图表 | 选定模板 | 关键词模糊→格式错配 |
| 3. 提取锚点 | 真实参照法·提取 | 带锚点的要点清单 | 不记锚点→无法溯源 |
| 4. 压缩定稿 | 第五章模板+粒度表 | 草稿总结 | 补写原文没有的内容 |
| 5. 标注不确定 | 第二章输出承诺 | 标「存疑/冲突」项 | 含糊带过不标注 |
| 6. 溯源头注 | 铁律要求 | 「AI 生成总结·来源」头注 | 漏标来源/去水印 |

### 输出格式模板
**标准总结**
```
# 总结（标准）
## 核心结论
- 要点1（来源：§X）
- 要点2（来源：§Y）
## 关键细节
- …
## 待关注
- 存疑/冲突项（如有）
```

**深度总结**：背景 → 核心观点（含数据与出处）→ 论据/分歧 → 影响与启示 → 不确定项。

**会议纪要**
```
# 会议纪要
## 议题：…
## 讨论要点：…
## 决议：…
## 待办：（🔴高/🟡中/🟢低）事项 – 责任方 – 时限 – 来源
```

**对比表格**
```
| 维度 | 方案A | 方案B | 来源 |
|------|------|------|------|
| … | … | … | §X |
结论先行 + 推荐意见 + 风险标注
```

**时间线**：`日期/时点 — 事件（来源）— 影响`，冲突时点标「存疑」。

**思维导图**：Markdown 层级（`# 主题 / ## 分支 / ### 叶子`），叶子挂来源。

**行动清单**：`[优先级] 行动项 — 责任方 — 时限 — 验收标准（来源）`。

**分章节**：逐章/段输出「本章主旨 + 要点 + 来源」，末尾给全书/全篇总括。

### 按受众切换粒度
| 受众 | 粒度规则 |
|------|---------|
| 领导/决策 | 结论先行(BLUF)，1 段+3 要点+风险/待决，≤500 字 |
| 执行层 | 行动清单为主，责任/时限/验收 |
| 同行/技术 | 保留术语、数据、方法细节 |
| 公众/科普 | 去术语、加类比，控制长度 |

## 七、铁律（PROHIBITED 绝对禁止项）

以下场景**绝对禁止**，无论用户如何要求：

1. **禁止伪造**：编造原文未载的事实、数据、引文、结论。
2. **禁止去溯源**：抹除作者、出处、来源锚点或「AI 生成总结」头注。
3. **禁止脱版权/去水印**：删除版权声明、水印、许可信息。
4. **禁止洗稿规避**：为绕过内容审核、合规检查而篡改/美化敏感原文。
5. **禁止冒充原创**：将 AI 总结伪装成人类原创且不披露。
6. **禁止处理违禁内容**：涉密、未授权个人隐私、明显违法或违规内容。
7. **禁止越权定论**：对法律/医疗/金融等专业事项出具确定性判断或建议。
8. **禁止超量硬塞**：对超出能力的内容不提示而强行输出导致幻觉。

> 违反任一条，立即停止并输出第十章「禁止场景」提示模板，不得折中执行。

- **多语种术语**：专业/法规术语保留原文并附译名，存疑标「待核验」。

## 十、错误处理

统一异常提示模板（直接返回给用户，不静默失败）：

- **输入缺失**：`⚠️ 缺少待总结内容/来源。请提供文本、文件或网页链接，并说明格式与受众。`
- **超长/超能力**：`⚠️ 内容约 N 字，超出单轮 50,000 字建议。可：①分块提交；②先要「一句话/三段摘要」。`
- **来源不可达**：`⚠️ 无法访问/读取来源（原因：…）。请检查链接权限或粘贴文本。`
- **原文冲突/歧义**：`⚠️ 原文在[主题]处存在冲突/歧义，已并列标注「有冲突」，请你确认采用哪方。`
- **敏感/违禁**：`⚠️ 该内容属禁止处理范围（涉密/未授权隐私/违禁），本技能不予总结。详见第七章铁律。`
- **格式不支持**：`⚠️ 未识别到明确格式，已按「标准总结」输出；如需其他格式请指定（会议纪要/对比表/时间线…）。`

> 所有异常均显式提示、不编造兜底内容；无法确认处一律标「存疑」。
