# AI 可观测性与生产监控

AI 视角：把「上线后的 AI」当需要持续盯防的系统——看得见（三大支柱）、测得准（AI 特有指标）、告得动（分级告警）、查得到（会话级追踪）。本技能管「线上运行质量」，与 LLM 评测（离线质量）互补。基调：敏感数据必须过滤、护栏监控不得关闭、监控留痕不得篡改。

## 定位

**何时用**
- 建监控：「AI 应用上线后要监控什么？」
- 查问题：「线上回答变差 / 报错 / 异常怎么定位？」
- 设告警：「什么情况要告警？阈值怎么定？」
- 管成本：「线上 Token 成本怎么实时盯？」
- 保安全：「护栏命中率、注入攻击怎么监控？」

**何时不用**
- 做离线模型质量评测（幻觉基准、评测集回归）→ 用 LLM 评测类技能。
- 要现成的监控 SaaS 产品 → 本技能是方法论与设计框架，需落到 Prometheus/Grafana、LangSmith、OpenTelemetry 等平台实施。
- 要改生产配置或模型 → 本技能不执行变更，只产出设计与规范。

## 一、能力边界

**In scope（本技能做）**
- 可观测性全景：三大支柱（日志 / 指标 / 追踪）+ AI 特有观测对象。
- 调用追踪与日志规范：LLM 调用追踪、Span 设计、会话级追踪、敏感信息过滤。
- 质量监控指标：幻觉率 / 拒答率 / 满意度 / 转人工率实时看板。
- 性能与成本监控：延迟 / 吞吐 / Token 成本实时追踪。
- 护栏与安全监控：护栏命中率 / 注入检测 / 敏感数据泄漏监控。
- 告警体系：分级告警 / 阈值设计 / 通知路由 / 告警疲劳治理。
- 平台与落地：埋点规范 / 工具选型 / 灰度期监控。
- 本地零依赖工具一键出：三大支柱清单、监控指标表、告警设计、追踪规范、落地路线。

**本技能不做（Out of scope，明确禁止越权）**
1. 不是监控产品——埋点 / 告警 / 看板需落到现有可观测性平台实施。
2. 不采集、不存储业务数据——工具仅做本地规则匹配，不联网、不调外部服务。
3. 不输出明文凭据 / PII / 对话原文——敏感信息必须过滤（见 references/02）。
4. 不直接修改生产配置或模型——变更由对应平台权限流程执行。
5. 不替代离线质量评测——幻觉率需结合抽样人工复核与评测集回归。
6. 不提供未经校准的绝对阈值——所有阈值与告警规则需按业务规模 / 风险等级校准。

## 四、常见错误与反模式

**反模式 ✗** 只监控服务器 CPU/接口，忽略幻觉率、Token 成本、护栏命中这些 AI 特有维度。
**替代方案 ✓** 在传统三大支柱之外，按 references/03（质量）、references/04（成本）、references/05（安全）补全 AI 特有观测对象。

**反模式 ✗** 把「无告警」当成「无问题」。
**替代方案 ✓** 结合离线评测集回归 + 抽样人工复核（references/03），监控与评测双轨交叉验证。

**反模式 ✗** 为「降噪」直接关掉护栏命中 / 注入检测告警。
**替代方案 ✓** 护栏与安全监控（references/05）必须保留；告警多就走分级 + 聚合，而非关闭监控。

**反模式 ✗** 在追踪 Span 里带上明文凭据 / 用户 PII。
**替代方案 ✓** 按 references/02 做敏感信息过滤，Span 只记录脱敏后的元数据。

**高频 Q&A**
- Q：AI 监控和普通监控区别？ A：多了幻觉率、Token 成本、护栏命中、Prompt 质量等模型特有维度（references/01）。
- Q：幻觉率能实时监控吗？ A：自动检测（规则/评估器）覆盖大部分，高危场景设实时告警 + 抽样人工复核（references/03）。
- Q：告警太多怎么办？ A：三级分级 + 阈值校准 + 聚合去重 + 值班轮转（references/06）。
- Q：工具要装依赖吗？ A：不需要，仅 Python 标准库、零网络。
- Q：支持哪些落地平台？ A：Prometheus/Grafana、LangSmith、OpenTelemetry 等；具体配置模板需按环境校准（官方链接待核验）。

## 六、关键事实速查

- **三大支柱**：Logs（日志）/ Metrics（指标）/ Traces（追踪）。AI 特有观测叠加：幻觉率、拒答率、满意度、转人工率、Token 成本、护栏命中率、注入检测率。
- **质量指标口径**：幻觉率=被判定为虚构/错误回答占比；拒答率=应答却拒绝占比；转人工率=升级人工会话占比（定义与监控方式见 references/03，口径待核验按业务校准）。
- **告警分级**：预警 / 告警 / 严重三级；阈值设计 + 聚合去重 + 通知路由（references/06）。
- **追踪规范**：LLM 调用级 Span + 会话级串联；敏感字段过滤（references/02）。
- **成本监控**：按模型/路由分层统计 Token 与延迟；蒸馏与缓存降本（references/04）。
- **平台选型**：Prometheus+Grafana、LangSmith、OpenTelemetry 等——具体配置模板与集成步骤以各平台官方文档为准（待核验）。
- **工具命令**：`pillars` / `metrics` / `alert` / `trace` / `plan`，无参数打印帮助。

## 七、铁律（PROHIBITED）

1. **禁止在监控埋点中采集 / 输出明文凭据、PII、对话原文**——敏感信息必须过滤（见 references/02）。
2. **禁止绕过护栏 / 安全监控**——护栏命中率、注入检测、敏感数据泄漏监控必须保留，不得为「降噪」关闭。
3. **禁止用本技能直接修改生产配置或模型**——本技能是方法论与设计框架，落地需由对应平台 / 权限流程执行。
4. **禁止删除 / 篡改监控数据或告警记录**——事故溯源依赖完整留痕。
5. **禁止把「无告警」等同于「无问题」**——需结合离线评测与抽样人工复核。
6. **禁止把外部平台文档当既成品**——阈值与告警规则需按业务校准，官方链接标注待核验。
7. **禁止泄露凭据到对话 / 代码 / 日志**——凭据仅可从保险库 `~/.ucvault_local` 读取，绝不进入对话、代码或日志。

## 九、示例

**示例 1（端到端场景：AI 客服上线监控）**
- 问题：AI 客服要上线，怎么从 0 搭监控？
- 加载：五（SOP 步 1-6）+ references/01、03、06。
- 答案框架：
  1. `pillars` → 确认日志/指标/追踪三支柱齐备，补 AI 特有维度（幻觉率、拒答率、Token 成本、护栏命中）。
  2. `metrics` → 出指标表，定义口径与采样方式（幻觉率配自动检测 + 抽样复核）。
  3. `trace` → 定 Span 规范，会话级串联，敏感字段过滤。
  4. `alert` → 三级告警（预警/告警/严重）+ 阈值 + 路由。
  5. `plan` + references/07 → 灰度期先监控再全量，埋点规范落地。

**示例 2（告警疲劳）**
- 问题：告警太多没人看。
- 加载：四（反模式）、references/06。
- 答案框架：先 `alert` 出分级设计 → 合并重复、按严重度路由到不同值班 → 校准阈值减少噪声，而非关闭告警。

**示例 3（安全监控）**
- 问题：怎么监控有人注入攻击？
- 加载：references/05、七（铁律 2）。
- 答案框架：保留护栏命中率 + 注入检测率 + 敏感数据泄漏监控三项；命中即告警，绝不因降噪关闭；监控输出本身也要过滤 PII。

## 十、错误处理

工具为纯本地 Python 标准库脚本，异常处理基础。以下为建议错误码体系与友好引导，弥补「argparse 默认提示生硬、无自定义错误码」的不足：

| 错误码 | 现象 | 原因 | 修正引导 |
|---|---|---|---|
| E-CMD | 输错命令，argparse 报 `invalid choice` | 命令名不在 {pillars,metrics,alert,trace,plan} | 运行 `python tools/observability_toolkit.py --help` 查看支持的 5 个命令 |
| E-ARG | 参数错误，argparse 报错退出 | 参数格式不对 | 按 `--help` 示例传参；本工具子命令多无需额外参数 |
| E-NOOUT | 期望结构化输出但为空 | 命令名正确但模式不匹配 | 确认子命令拼写；无参数时默认打印帮助并正常退出 |
| E-NET | 脚本尝试联网失败（不应发生） | 环境被污染或误改 | 本工具纯本地零网络，若报网络错误立即排查运行环境 |
| E-REF | 引用的 references 模块缺失 | 文件被误删 / 路径变更 | 确认 `references/01`-`references/08` 完整 |
| E-PII | 监控输出含敏感字段 | 未启用敏感信息过滤 | 按 references/02 的 Span 设计做脱敏，绝不输出明文凭据 / PII |
