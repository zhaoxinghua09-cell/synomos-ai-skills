# AI 模型资产管理（LLMOps）

AI 视角：把企业的 AI 资产当需要持续治理的「阵地」——建台账（看得见）、管版本（回得去）、控上线（走得稳）、盯漂移（防退化）、算成本（控得住）。基调：上线 / 退役须审批、历史版本不得物理删除、模型卡密钥不得泄露、漂移告警不得关闭。本技能管「资产与工程」，与企业 AI 治理（管制度）互补。

## 定位

**何时用**
- 建台账：「我们的 AI 资产有哪些？都登记了吗？」
- 管版本：「模型 / Prompt 升级怎么管理？出问题怎么回滚？」
- 控上线：「新模型上线要什么流程？旧模型怎么退役？」
- 盯漂移：「模型效果变差了怎么发现？」
- 算成本：「AI 调用成本怎么核算和控制？」

**何时不用**
- 做离线模型质量评测基准 → 用 LLM 评测类技能。
- 要现成的资产管理平台 → 本技能是方法论与流程框架，需落到 MLflow、LangSmith、内部平台实施。
- 要改生产配置或切流量 → 本技能不执行变更，只产出模板 / 检查 / 流程。

## 一、能力边界

**In scope（本技能做）**
- 资产全景与台账：模型 / Prompt / 知识库 / 评估集 / Agent 配置五类资产登记。
- 模型卡与注册：Model Card 字段规范、注册流程、元数据管理。
- 版本管理：模型 / Prompt / 知识库版本化、灰度发布、一键回滚。
- 上线下线管理：上线审批、退役下线、废弃处置与迁移。
- 漂移监控：数据漂移 / 概念漂移 / 模型漂移、监控指标与告警阈值。
- 成本治理：Token 成本核算、预算控制、路由分层、蒸馏与缓存降本。
- 治理制度与流程：角色职责、审批流、审计留痕。
- 本地零依赖工具一键出：盘点清单、模型卡模板、生命周期检查、漂移监控要点、成本治理清单。

**本技能不做（Out of scope，明确禁止越权）**
1. 不是资产管理平台——台账 / 版本 / 监控需落到现有工具链（MLflow、LangSmith、内部平台）实施。
2. 不执行上线 / 退役 / 切流量等生产变更——须走治理审批流程（references/07）。
3. 不物理删除模型版本或知识库快照——回滚依赖历史版本，删除须治理流程明确废弃。
4. 不输出模型卡中的明文凭据 / 密钥——密钥字段从保险库读取。
5. 不提供未经校准的绝对阈值——漂移阈值、成本预算需按业务规模校准。
6. 不替代企业 AI 治理制度——本技能管资产与工程，制度归治理流程。

## 四、常见错误与反模式

**反模式 ✗** 模型 / Prompt 升级不固化版本，出问题没法回滚。
**替代方案 ✓** 每版固化（模型 + Prompt + 知识库快照），发布走灰度，异常一键回退（references/03）。

**反模式 ✗** 资产不登记，谁在用哪个模型都不知道。
**替代方案 ✓** 建五类台账：模型、Prompt、知识库、评估集、Agent 配置，登记版本 / 负责人 / 状态 / 依赖（references/01）。

**反模式 ✗** 发现模型变差靠用户投诉。
**替代方案 ✓** 漂移监控三轨：线上指标（拒绝率/满意度）+ 定期评测集回归 + 数据漂移检测（references/05）。

**反模式 ✗** 为降本直接砍掉护栏或质量评测。
**替代方案 ✓** 成本治理（references/06）用路由分层 + 蒸馏 + 缓存降本，不以牺牲安全与质量为代价（见七·铁律 4）。

**高频 Q&A**
- Q：资产台账要管什么？ A：五类——模型、Prompt、知识库、评估集、Agent 配置，每类登记「版本+负责人+状态+依赖」（references/01）。
- Q：模型升级出问题怎么回滚？ A：版本管理先行，灰度发布，一键回退上一可用版本（references/03）。
- Q：怎么发现模型变差？ A：漂移监控三轨并行（references/05）。
- Q：工具要装依赖吗？ A：不需要，仅 Python 标准库、零网络。
- Q：能和 MLflow/LangSmith 对接吗？ A：本技能是框架，集成步骤需按企业环境校准（官方链接待核验）。

## 六、关键事实速查

- **五类资产**：模型、Prompt、知识库、评估集、Agent 配置（每类登记版本+负责人+状态+依赖）。
- **模型卡（Model Card）字段**：模型标识、版本、训练/来源、用途与限制、指标、依赖、责任人、密钥字段（密钥从保险库读取，不落地明文）——详见 references/02。
- **版本管理**：模型/Prompt/知识库版本化 + 灰度发布 + 一键回滚（references/03）。
- **生命周期阶段**：`register` / `launch` / `monitor` / `retire`（lifecycle 命令 `--phase` 仅支持这 4 值）。
- **漂移三类**：数据漂移 / 概念漂移 / 模型漂移；监控指标 + 告警阈值见 references/05（阈值待核验按业务校准）。
- **成本治理**：Token 成本核算、预算控制、路由分层、蒸馏与缓存降本（references/06）。
- **治理流程**：角色职责、审批流、审计留痕（references/07）。
- **工具命令**：`inventory` / `modelcard` / `lifecycle` / `drift` / `cost`；`verify/` 目录含质量与安全校验脚本（部分路径引用待核验，以实际文件为准）。

## 七、铁律（PROHIBITED）

1. **禁止未经审批上线 / 退役模型**——上线审批、退役下线须走治理流程（references/07），不得私自切换生产流量。
2. **禁止删除 / 覆盖模型版本或知识库快照**——回滚依赖历史版本，版本不得物理删除（除非治理流程明确废弃）。
3. **禁止泄露模型卡中的凭据 / 密钥字段**——模型卡元数据中的密钥必须从保险库读取，绝不进对话 / 代码 / 日志。
4. **禁止把成本数据当唯一治理依据**——需结合质量 / 漂移，避免为降本牺牲安全与质量。
5. **禁止绕过漂移监控降级告警**——数据 / 概念 / 模型漂移告警不得为「省心」关闭。
6. **禁止用本技能直接改生产配置**——本技能是方法论与流程框架，落地需对应平台权限。
7. **禁止泄露凭据到对话 / 代码 / 日志**——凭据仅可从保险库 `~/.ucvault_local` 读取，绝不进入对话、代码或日志。

## 九、示例

**示例 1（端到端场景：AI 资产从混乱到清晰）**
- 问题：公司 AI 资产一片混乱，出了事找不到责任人。
- 加载：五（SOP 步 1-6）+ references/01、02、07。
- 答案框架：
  1. `inventory` → 五类资产盘点清单，登记版本/负责人/状态/依赖。
  2. `modelcard` → 每个模型补 Model Card（密钥字段标「从保险库读取」）。
  3. `lifecycle --phase register/launch` → 走审批流登记与上线。
  4. `drift` + `cost` → 上线后盯漂移与成本。
  5. references/07 → 变更全程审计留痕。

**示例 2（回滚）**
- 问题：新模型上线后效果暴跌，怎么回退？
- 加载：references/03、七（铁律 2）。
- 答案框架：因每版已固化快照，直接一键回退到上一可用版本；严禁为「腾空间」物理删除旧版本。

**示例 3（成本治理）**
- 问题：AI 调用成本失控。
- 加载：references/06、七（铁律 4）。
- 答案框架：`cost` 出成本治理清单 → 路由分层（贵模型仅高危走）+ 蒸馏 + 缓存降本；不以关闭质量评测 / 护栏换成本。

## 十、错误处理

工具为纯本地 Python 标准库脚本，仅 `lifecycle` 有基础参数校验，其余命令无输入校验。以下为建议错误码体系与友好引导，弥补「错误提示生硬、无错误码」的不足：

| 错误码 | 现象 | 原因 | 修正引导 |
|---|---|---|---|
| E-CMD | 输错命令，argparse 报错 | 命令不在 {inventory,modelcard,lifecycle,drift,cost} | 运行 `python tools/llmops_toolkit.py --help` 查看 5 个命令 |
| E-PHASE | `lifecycle --phase` 值非法，提示「仅支持 register/launch/monitor/retire」并退出码 2 | `--phase` 不在允许集合 | 改用合法阶段值；查看 `--help` |
| E-ARG | 参数格式错误，argparse 报错 | 参数不对 | 按 `--help` 示例传参；多数字命令无需额外参数 |
| E-NOOUT | 期望清单但为空 | 子命令拼写对但模式不匹配 | 确认命令；无参数时默认打印帮助 |
| E-NET | 脚本联网失败（不应发生） | 环境异常 | 纯本地工具，若报网络错误立即排查运行环境 |
| E-REF | references 模块缺失 | 文件误删 | 确认 `references/01`-`references/08` 完整 |
