# agent-learn-external-skill（向外部 skill 学习 · Track A）

**定位**：本技能是「学习吸收器」而非「安装器」。它用**真实参照法（Real-Reference）**把外部优秀 skill 的写法拆解为可复用干货，对照自身产出**差距清单（Gap List）**与**补强项（Fix-Item）**，再固化为你自己的技能/记忆。

**何时用**：用户说「去市场学 XX 类」「吸收同类 skill 写法」「对标一下别人的包」「别人这技能比我好在哪」时调用。
**何时不用**：① 想直接安装/发布外部 skill（本技能禁止）；② 想让我替你写新功能代码；③ 来源是含明文密钥的私有脚本。

---

## 一、能力边界

**能做（Track A 只读吸收）**
- 检索并下载外部优秀 skill 到**临时目录**只读分析（不进 `skills/` 目录）。
- 抽取结构化干货：错误码速查、坑位清单、日志格式、触发设计、SOP 模板。
- 对照自身 skill 产出「差距清单 + 补强项 + 固化指引」。
- 把补强项写回你自己的 skill / 记忆 / 新建 skill（标注来源与日期）。

**不能做**
- 不安装、不启用、不发布任何外部 skill。
- 不改头换面把别人成果当自己的发布（冒名）。
- 不整段搬运外部原文（仅吸收方法，注明出处）。
- 不读取、不转存、不分析含明文密钥的脚本。

---

## 二、输入约束与输出承诺

**输入约束**
- 必须：用户明确触发 + 至少一个外部来源（市场名 / 仓库 URL / 文档链接）。
- 可选：期望对标的技能类型、关键词，或要补强的自有 skill 路径。
- 禁止输入：含明文密钥的脚本、未授权私有仓库、非公开来源。

**输出承诺**
- `差距清单（Gap List）`：逐项列出「对方有 / 我有 / 差异 / 是否补强」。
- `补强项（Fix-Item）`：含优先级（P0/P1/P2）与固化位置建议。
- `固化指引`：明确 Edit 哪个文件、补哪一段、标注来源日期。
- `临时文件清理确认`：分析完即删，不留痕。
- 绝不自动安装/发布任何外部 skill；绝不把密钥带入对话或输出。

## 四、常见错误与反模式（FAQ + 高频 Q&A）

**反模式（PROHIBITED 行为，见第七章）**
- ❌ 把市场下载的 skill 改个名直接发布 = 冒名剽窃。
- ❌ 整段复制 SKILL.md 原文 = 搬运，应只吸收方法并注明出处。
- ❌ 把含密钥的脚本当学习样本外传 = 密钥泄露。
- ❌ 不写来源日期 = 无法追溯、破坏 AI 护照可溯源性。

**高频 Q&A**
- Q：它会帮我自动装好外部 skill 吗？A：不会，Track A 只吸收不安装。
- Q：学完能直接用到我技能里？A：会给出固化指引，但写盘需你确认/授权，且只补方法不抄原文。
- Q：没有来源能学吗？A：不能，必须用户提供市场/仓库/链接，否则拒绝。
- Q：中文以外语言能用？A：支持 zh-CN/en/ja/ko/es/fr/de/ar，跟随输入语言回复。
- Q：分析时遇到密钥怎么办？A：立即停止，不读取、不转存、不输出，提示用户。

## 五、标准 SOP（步骤表）

**核心方法：真实参照法（Real-Reference）**——对照外部优秀 skill 的写法，逐项比对自身 skill 的「结构/内容/边界/示例」，找出可补强的**具体差异点**再固化；不照抄、只吸收方法。

| 步 | 动作 | 产出 | 红线 |
|---|---|---|---|
| 1 检索 | `find-skills` 或 WebSearch / Bash 调 `https://lightmake.site/api/v1/search` 找同类优秀 skill | 候选清单（含来源） | 不碰未授权私有库 |
| 2 下载 | 拉到**临时目录**（如 `学习计划/_tmp/`），只读读取 SKILL.md + 脚本 | 本地只读副本 | 不进 `skills/` 目录 |
| 3 解析 | 拆结构/内容/边界/示例/坑位 | 要素清单 | 遇密钥立即停止 |
| 4 抽干货 | 用**差距清单模板**比对自身 skill | Gap List 草稿 | 不整段搬运原文 |
| 5 定补强 | 按**补强项判定标准**排 P0/P1/P2 | Fix-Item 列表 | 不冒名 |
| 6 固化 | Edit 自有 SKILL.md / 写记忆 / 建新 skill，标注来源+日期 | 已落地的补强 | 不改头发布 |
| 7 清理 | 删除 `_tmp/` 临时文件 | 清理确认 | 不留痕 |

**差距清单模板（Gap List）**
```
| 维度 | 对方做法 | 我方现状 | 差异 | 是否补强 | 优先级 |
|------|---------|---------|------|----------|--------|
| 错误码 | 有速查表 | 无 | 缺 | 是 | P0 |
```

**补强项判定标准**
- `P0`：对方有、我方缺且高频刚需（如错误码速查、边界声明）→ 必补。
- `P1`：显著提升可用性但非必须（如触发示例、IO 样例）→ 建议补。
- `P2`：锦上添花（如多语种、渐进披露）→ 视资源补。
- 复发≥3 次的同类差异 → 晋升为独立 skill 或记忆条目。

## 九、示例

**输入（用户）**
> 「吸收 `wechat-official-tool`，看我们 `wechat-article-full-workflow` 能补什么。」

**处理（SOP 1→7）**
1. 检索定位该 skill；2. 下载到 `_tmp/` 只读；3. 解析出「微信 API 错误码速查 + 永久素材坑」；4. 差距清单：我方缺错误码表；5. 补强项 P0：补 `45003/40001/40006/40007/40164/48001` 速查 + 标注「40007 草稿只认永久 media_id」；6. Edit 我方 SKILL.md 补该段并标来源日期；7. 清理 `_tmp/`。

**输出（节选）**
```
[差距清单] 微信 API 错误码：对方有速查表 / 我方无 → 补强 P0
[补强项] 在 wechat-article-full-workflow 增加「错误码速查(45003…48001)」+ 永久素材坑(40007)
[固化指引] Edit SKILL.md → 第二节追加，标注「来源 wechat-official-tool @2026-08-17」
[清理] _tmp/ 已删除 ✅
```

## 十、错误处理

| 异常 | 现象 | 处理 |
|---|---|---|
| 检索无结果 | 市场/接口返回空 | 换关键词或来源，仍无则告知用户并停止 |
| 下载失败 | 链接失效/403 | 提示来源不可用，不重试私有库 |
| 命中密钥 | 样本中含明文 token/key | 立即停止、不读取、不转存、不输出，提醒用户 |
| 来源未授权 | 私有仓库无权限 | 拒绝学习，建议用户提供公开来源 |
| 无用户触发 | 未给来源直接要求对标 | 拒绝，要求先给市场/仓库/链接 |
| 补强冲突 | 与既有安全护栏冲突 | 放弃该补强，保留护栏并说明原因 |
